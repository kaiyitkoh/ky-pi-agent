## Notes on the fixes

**WR-BC3-1.** The JWT rule is anchored with `(?<![A-Za-z0-9_-])`, so each run has only one start. The curl rule's separator is `(?: +|=)`, its user part starts with a non-`=` character and is bounded at `{0,256}`, and its password part is unbounded. The password is the last part of the rule, so it cannot fail and force a rescan. The header and DIAGNOSTICS.md now state the property that is actually true: every unbounded run either ends its rule or is anchored to one start.

**WR-BC3-2.** The value bound is removed, and the closing quote is optional. The spacing may also cross one newline. This applies to logs only, so over-masking a YAML key on the following line is an accepted cost.

**WR-BC3-3.** The command is now `git -c log.showSignature=false log --no-show-signature --no-color --format=%P|%at|%ct`. Each row is matched strictly against `^[0-9a-f]{40,64}\|\d+\|\d+$`. This rejects a merge commit, a root commit, and any line that does not parse. The tolerance is `COMMIT_CLOCK_TOLERANCE_MS = 120_000`. I chose a fixed tolerance over reflog-based detection because it is the simplest robust option, and the reflog can be rewritten by the same model the check guards against. The IN-BC3-6 residuals, and the new two-minute window, are listed in WORKFLOWS.md §4.

**WR-BC3-4.** The checkbox is stripped both when a task is pinned and when it is compared. Ledgers pinned before this change therefore do not refuse even once.

**WR-BC3-5, where the copy is stored.** This deviates from the orchestrator's wording on purpose. The pinned SPEC.md copy is written beside the ledger, as `<git common dir>/kypi-ledger/<slug>.<worktree>.SPEC.md`, not inside `.pi/work/<slug>/`. There are two reasons:
- `work-artifacts.ts` and `work-artifacts.test.ts` fix the work directory at exactly four artifacts, each with a named consumer.
- The ledger directory is behind the safety path guard, so the model can neither read nor edit the copy.

The copy is used only when its hash matches the signed `specHash`. If it does not match, the confirm says the change cannot be shown. The refusal gives `!cp "<copy>" ".pi/work/<slug>/SPEC.md"`. Pi's user `!` bash is not routed through the guard, so the user can run it.

**WR-BC3-5, the confirm.** It now shows only the changed task and SPEC lines, as `-` (pinned) and `+` (now). The diff trims the common head and tail and runs an LCS on the middle. If the middle is larger than 1,000,000 cells, it lists every middle line instead.

**WR-BC3-5, line budget.** The `.pi/extensions/execute` directory budget was RAISED from 900 to 970: 964 raw lines, of which `ledger.ts` is 241. No frozen per-workflow ceiling moved. `execute/index.ts` is 230, against a frozen ceiling of 250.

## Accepted and deferred

**IN-BC3-7 (accepted).** Verification output in the ledger and MR body stays name-redacted. The ledger entry is also a log on disk, which the name rules exist to protect. A `token: [redacted:9 chars]` in an MR is a smaller cost than a credential from test output reaching a merge request in a public or shared GitLab project. This was already documented as deliberate in the iteration-2 report.

**IN-BC3-4 (deferred).** The fix is to make `/mode` and the planner pin share one picker, or to reword the advice. Sharing a picker means choosing whether pins should check configured auth. That changes which model subagents get on a machine without the first candidate's key, so it is a routing-policy decision rather than a cheap fix. Until then, the misleading advice costs only a redundant re-run.

**IN-A3-3 (deferred).** `terraform -chdir=infra plan` returns `confirm` on both heads. That is a false positive, not a bypass. Changing it means changing the infra classifier's subcommand parsing, which is part A's safety scope. It was not in this pass's list, and it deserves its own evasion-corpus rows (`-chdir=x apply` must still confirm).

## Decisions recorded

### CR-BC2-1 and WR-BC2-6: two rule sets, one table
`.pi/lib/secret-patterns.ts` now exports three things:

- **`SHAPE_PATTERNS`**: every shape rule. These are `sk-`, `AKIA`/`ASIA`, `ghp_` and its family, `github_pat_`, `glpat-`, `xox?-`, `AIza`, `pt-`, `ABSK`, a PEM header, JWT, URL userinfo, `curl -u` and `mysql -p`. They also include a bearer value of **at least 16 token characters**, so prose and code such as `// send the Bearer token` stay readable.
- **`LOG_ONLY_PATTERNS`**: a bearer value of any length, and the credential-name assignment rule.
- **`SECRET_PATTERNS`**: shape rules first, then the log-only rules.

Who uses which:
- `maskSecrets` and `redactString` use every rule. They serve the wire log, the audit, provider errors, evidence rows and the `PROGRESS.md` verification output.
- `maskSecretShapes` and the new `redactForModel` use the shape rules only. They serve the reviewer contract, the design-review prompt and the MR body.

The name rule is now bounded:
- key suffix `{0,40}`;
- spacing `[ \t]{0,16}`;
- values `{0,512}`, with `\n` excluded from quoted values.

Each start position therefore costs O(1). I did not add the `(?<![A-Za-z0-9])` lookbehind the review suggested, because it would stop `sessionToken` and `accessToken` from matching. The bound alone makes the rule linear. The header's ReDoS claim was rewritten so it is true.

### WR-BC2-1
The `source === "extension"` exemption is removed, not narrowed. `/quick` and `/execute` guard before they arm, so the backstop refuses their prompt only when the model changed in between. The run then stays pending, records nothing, and the next prompt disarms it (verified in the iteration-2 review against Pi 1.1.0). `/execute`'s own comment that cited the exemption still reads correctly, because its pre-check stays useful.

### WR-BC2-2: rule chosen
After the existing ancestry check, `onlyCommitsSince` requires every commit in `base..HEAD` to meet two conditions:
- it has exactly one parent;
- both its author time and its committer time are at or after the arm second. Git stores whole seconds, so the comparison uses floor seconds.

Several fresh commits are accepted, so a follow-up fix commit is not punished. I did not require "exactly one", because the D-01 completion rule is about producing a commit, not about counting them. `RunState` gained `armedAt`.

Documented residuals in docs/WORKFLOWS.md section 4:
- a teammate's commit made after arm time and pulled in by fast-forward still passes;
- a commit whose dates were forged with `GIT_AUTHOR_DATE` still passes.

One existing unit test (`endRun() disarms ...`) asserted that a commit made before arming was accepted. It now asserts only that the run ends, which is what the test's name says it checks.

### WR-BC2-3 and WR-BC2-4
`PinnedTask` gained `line` (the full PLAN task line) and `requirementIds`. Each pin also stores `specHash`, a SHA-256 of the SPEC.md bytes.

A new `pin` ledger row kind carries `{allowance, tasks, specHash, reason}`:
- `pinnedPlan`, `pinnedAllowance` and `pinnedTasks` read the latest `base` or `pin` row.
- `ledgerBase` and `latestRepin` still read `base` rows only, so a `pin` row never reads as a rebase.

`/execute <slug> --repin` works as follows:
- It shows the pinned and current allowance, task lines and whether SPEC.md changed, through `ctx.ui.confirm`. With no UI it refuses.
- On approval it appends a `pin` row. It never moves the drift base and never prompts the model.

Other changes:
- `--rebase-base` re-pins the same content alongside the base.
- An allowance change is now accepted with `--repin`.
- `/execute` and `/review` both compare through one `pinMismatch`.

**Compatibility.** Ledgers written before this change lack `line` and `specHash`, so they refuse until the user runs `--repin`. That is fail-closed. `/review` used to skip the task check on a pin without `tasks`. It now refuses those too, for consistency.

I did not move the first `base` row to `before_agent_start`, which the review raised as optional. `--repin` already makes a PLAN edit after a run that never started cheap to accept.

### WR-BC2-5
- **Owners carry time.** Each owner is recorded as `{ pid, at }`. An owner that has not written the pin for 24 hours is dropped even when its pid answers, which covers Windows pid reuse and an `EPERM`-answering service. A re-pin within 1 hour keeps the recorded time, so an identical pin stays a no-op write and the existing mtime test holds. A bare-pid owner from an older marker counts as expired.
- **A session never inherits a pin.** At `session_start`, while any session's pin is in the file (`plannerPinHeld`), a session writes its own mode's pin, `cheap` included. With no pin in the file, a `cheap` session writes nothing.
- **`/mode` reports what runs.** It reads `subagents.agentOverrides.<agent>` (`readAgentOverride`). When that differs from the route, it says which model subagents actually run and that re-running the mode command re-pins it.
- **Accepted residual: no lock.** The review's third point is the unlocked cross-process read-modify-write. I documented it in ROUTING.md rather than adding a lock file. The worst outcome is a lost owner entry, which either restores early (the cheaper direction) or holds until the 24-hour expiry. A stale-lock recovery path would add more complexity than the residual costs.

### IN-BC2-2
Removing `bg_enable` from `full` in the table alone did nothing, because `applyProfile` returned early for `full`. `full` now goes through the same filter, and the only entry that excludes `full` is `bg_enable`. An explicit `--tools` allowlist is still never narrowed, because `index.ts` now skips narrowing entirely in that case rather than mapping it to `full`.

### IN-BC2-5
A failed or partly dropped design pass now adds a doubt to the "Open the MR anyway?" confirm, instead of only showing a warning. docs/QUALITY.md says so.

## Deferred

### IN-BC2-3 (rest): the unborn-HEAD message
Only the `claimWorkflow` reorder was applied. On a repository with no commit, the arm already refuses (fail-closed), just with git's own text. Adding a `rev-parse --verify HEAD` pre-check to both `/quick` and `/execute` would spend lines in `/quick`, which sits at 98 of its frozen 100, for a message-only gain.

### IN-BC2-4: `/quick` refuses an overfull context, where the backstop only warns
Making `/quick` drop the context check, as `/execute` does, is a one-line change. But it changes the refusal contract of the command whose router is `planRoleCall`, and `quick-workflow` has no context-usage fixture to prove it. Choosing between "warn everywhere" and "refuse everywhere" is better made together with IN-C-9, the `/new` mode carry-over, which is also deferred.

### IN-BC2-9: the base typecheck can leave a `.tsbuildinfo` in the tree
The safe fixes all touch the gate path:
- `--incremental false` breaks `composite` projects (TS6379), which would turn a passing typecheck into a reject.
- Excluding `*.tsbuildinfo` misses a configured `tsBuildInfoFile` elsewhere.
- Reordering puts a typecheck in front of every dirty-tree refusal.

Common templates already ignore `*.tsbuildinfo` (create-next-app does). The failure is loud and fail-closed: the settle rejects and names the file.

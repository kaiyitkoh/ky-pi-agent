## Decisions recorded

### CR-C-1
- `deriveNeed` no longer scans the branch. `image` comes only from `extra.image`. The `input` backstop passes `event.images.length > 0`. `NeedContext` lost `sessionManager`.
- I checked that pi-ai 1.1.0 `dist/api/transform-messages.js` (`downgradeUnsupportedImages`) replaces user and tool-result images with a placeholder for a text-only model. A past image is therefore never a reason to refuse.
- Mode commands and `/escalate` never carry an image need.

### CR-C-2
- `RunSingleShotRoleOptions.need` is removed. `runSingleShotRole` builds the need itself with `nestedNeed(request, route.reasoningEffort)`:
  - tokens = (system prompt + messages + tools JSON) / 4;
  - `image` = an image block in the request's own messages;
  - `thinkingRequested` = the route has an effort.
- Callers can no longer pass the session's need. The four quality call sites dropped their `deriveNeed` import.

### CR-C-3
- `resolveBedrockRef` is factored out of `pickConfiguredCandidate` in `modes.ts`, and `agentOverridesFor` uses it as well.
- An invalid prefix setting refuses the pin with the setting's name in the reason.

### CR-C-4 (option chosen: owner pids in the marker)
I chose the simplest option that stays correct. The marker is now `{ hadOverrides, keys: { <agent>: { had, value } }, owners: [pid] }`:
- A write adds this pid to `owners`.
- `restorePlannerPin` (called at `session_start` and `session_shutdown`) removes its own pid and every pid that `process.kill(pid, 0)` reports dead. It restores only when no owner is left.
- Subagent children (`PI_SUBAGENT_CHILD=1`, verified in pi-subagents 0.76.1 `src/runs/shared/child-runtime-config.js:6`) skip the bookkeeping entirely.
- A legacy `{had, value}` marker is still restored.
- Residual risks, documented in ROUTING.md: two sessions pinning different modes share the file (last writer wins), and a recycled pid can keep a stale pin alive until that process exits.

I rejected a per-spawn model override because it would rely on the cheap model passing the right `model` argument on every dispatch.

### CR-C-5
`.pi/lib/secret-patterns.ts` is the one table, and both `diagnostics/redact.ts` and `safety/audit.ts` import it. `safety/` still imports nothing from `diagnostics/`.
- The table covers the union of both old tables, plus `glpat-`, `ABSK`, bearer tokens of any length, URL userinfo passwords and the generic key-name assignment rule (`password|passwd|secret|token|api_key|access_key|authorization|credential`).
- A named `keep` group preserves the key name or the `Bearer ` / `-u ` prefix.
- The header-key rule now also tests the snake-cased key, so `apiKey`, `accessToken` and `secretAccessKey` match while `maxTokens` does not.
- The ReDoS fixture unit changed `Bearer sk-AKIA` to `Bearer, sk-AKIA`, because a bearer token of any length is now a real match rather than a near miss. It still redacts 1 MB in under 2 s.

### WR-C-1
Pi gives extensions no way to write the default model, and writing `settings.json` behind `SettingsManager` would be overwritten from memory. Instead, the revert message says when the refused model is still the saved default (`pi.getSettings()`) and how to change it. This is the review's documented fallback.

### WR-C-2
- The revert checks the result of `setModel`, and also catches a throw.
- A failure is reported as a failure.
- A success names the resulting thinking level. Pi resets it to the per-model or global default on every switch, so the message documents the reset rather than restoring the earlier level, which no API exposes at `model_select` time.

### WR-C-3
When only the thinking block fails, `model_select` calls `pi.setThinkingLevel("off")` and keeps the model.

### WR-C-4
- The backstop lets `source: "extension"` prompts through.
- `/execute` now runs the executor guard on the session model (image, thinking and R1; not context) before it arms anything.
- `/quick` already had `planRoleCall`.

### WR-C-5
A context-only failure warns and points at `/compact`, and the prompt goes through to Pi's own compaction. Image, thinking and R1 still refuse.

### WR-C-7
`captureRequestPayload` bounds first, then redacts. The 16-hex history hash is now taken over the raw messages array, because redacting all history first is exactly the cost being removed. A truncated SHA-256 over a whole conversation does not expose its content.

### WR-C-8 and WR-C-9
- After the task POST, the read loop runs inside `try/finally`, and every exit except a completed answer cancels the remote session. The abort path no longer cancels separately.
- `status_idle` counts only after `session.status_running` or an `event_start` frame.
- An empty answer is an error.
- The stream request sends `Accept: text/event-stream`.
- The event order is a new item in the RUNBOOK Qoder live check.

### WR-C-10
I chose re-stat plus no-clobber over unique rotated names, because unique names would change every reader and the prune logic:
- `appendJsonl` re-stats the live file before rotating, so a stale cache cannot rotate a file another process already rotated.
- `rotate` never renames onto an existing rotated file (`existsSync(dst)`).
- A rotation that was skipped while the live file is still over the cap counts as a failure for backoff.

The remaining window is microseconds between the check and the rename. That is narrowed, not locked, and the module docstring says so.

### WR-C-11

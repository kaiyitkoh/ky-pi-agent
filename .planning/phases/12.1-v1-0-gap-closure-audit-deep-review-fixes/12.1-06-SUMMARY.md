## Doc deltas for Plan 10 (docs/QUALITY.md, docs/WORKFLOWS.md)

- Design-review signals: file span >= 8, a loop body (next 8 lines) containing a query-like call on an added line, a changed path matching schema/migration(s)/models/.prisma/.sql/.graphql, an added or removed `export` line in a JS/TS file, or escalation. REVIEW.md always carries a Design review section.
- Merge-base rule: remote-tracking `staging` first, local `staging` second, otherwise /review refuses with a fetch hint.
- Verdict gating: Partial or Missing verdict -> approval prompt (a surviving BLOCKER still stops without approval); the MR body lists every verdict.
- MR audit row: tool `glab`, event `mr_create`, allow/block, no body text.
- Reviewer: one retry on a prose tool call; no forced tool choice (the single-shot dispatcher exposes none).

## Decisions

- The verdict rule sits after the BLOCKER rule in `decideWorkflowStop` (plan text said before it). Putting it first would let an approvable stop mask a no-approval BLOCKER stop, which is weaker; the behaviour row ("Missing or Partial and no BLOCKER") is satisfied either way.
- `cwd` is a required field of `OpenMrDeps`, so an MR cannot be opened without an audit destination; existing tests were updated.
- Forced tool choice on the corrective retry was not added: `runSingleShotRole` has no such option and adding one is a routing change outside this plan.
- Design pass is additive and fails open; a design BLOCKER enters refute-or-promote like any other.

## Decisions recorded

### CR-A-1
- **New refusal cause.** The new cause is `generated-script`. A shell runner refuses any interpreter that reads its script from a pipe or an input redirect, at all times, whatever the script holds. That covers no operand, `-`, `sh -s`, and a bare-word operand such as `bash -o pipefail`.
- **`xargs` and `parallel`.** Both are refused when they run an interpreter on piped input.
- **Write-then-run.** A file that the same command writes and then runs is refused. Files are matched by basename, because a `cd` may sit between the write and the run.
- **False-positive check.** These stay allowed: `cat x | python script.py`, `node -e ...`, `curl ... | jq`, `git diff | node scripts/x.mjs` and `sh scripts/check.sh`. `curl ... | sh` is now refused, which is deliberate.

### CR-A-2
- **Rebase.** `rebase -i` is not refused on a feature branch. Its todo can run `exec` lines only through an editor that the guard already gates (`-c sequence.editor` and `GIT_SEQUENCE_EDITOR` both block). WR-A-1 lists `git rebase -i HEAD~3` as a common command that must keep working.
- **Read tables.** Every `rebase` is now a write when HEAD is protected.

### CR-A-3
- **Where paths are resolved.** Path arguments and redirects are classified in two directories: the session cwd and the `cd`/`pushd`/`env -C` target.
- **Home targets.** `cd ~`, `cd ~/x` and a bare `cd` resolve to home.
- **Unresolvable `cd`.** After a `cd` whose target cannot be resolved, any relative argument is refused. git and glab are exempt, because their arguments are revisions and subcommands, and the branch check already treats an unresolvable `cd` as protected.
- **Accepted false positive.** `cd "$D" && npm test` is now refused.

### CR-A-6
- **Scratch locations.** Bash writes to device files, `/tmp` and the OS temp dir (a new `tempDir` fact) are allowed. Every other out-of-project bash write blocks, as the write tool does.
- **Write operands covered.** `tee`, `cp`, `mv`, `install`, `ln`, `dd of=`, `sed -i`, `rm`, `rmdir`, `touch`, `truncate`, `shred`, `curl -o` and `wget -O`.

### CR-A-7
- **Verdict.** Writes to extension code inside the project return the existing `ask` verdict, which now carries a title. The user confirms through `ctx.ui.confirm` in the TUI or RPC. json, print and subagent children refuse.
- **Outside the project.** The same paths still block, which is stronger.
- **Two asks in one command.** These block, as two pushes did before.

### CR-A-8
- **No live regeneration.** No live stub was regenerated. RB-12-08 tells the owner to re-run the full bootstrap on each machine.

### WR-A-7
- **What `--global-setup` accepts.** It accepts a current, fail-closed stub or a user-level git package as the single delivery path. It refuses an absent stub and a stub that predates CR-A-8.
- **The owner's machine.** Its current stub predates CR-A-8. `--global-setup` will therefore fail there until a full run rewrites the stub, which is intended.

### WR-A-8
- **Feature-branch pushes.** `git push` with no refspec now asks on `feat`, because it resolves to `feat` on `origin`. The seven affected rows carry `verdictOnFeature: "ask"`, so the corpus pins ask, not allow.

### WR-A-5
- **Variables used as arguments.** A secret-shaped variable passed as an argument stays allowed (`curl -H "PRIVATE-TOKEN: $GITLAB_TOKEN"`), so it does not train the user to disable the guard.
- **Printing commands.** Only commands that print the variable block.

### WR-A-2
- **The `~/` change.** A leading `~/` in command position is now literal. `~/bin/git push origin main` is classified as git and still blocks (EV-122's text was updated). `~user/x` is still refused.

### IN-A-4 (deferred)
- **Why deferred.** Making protected branches configurable (`kyPiAgent.protectedBranches`) needs two decisions from the user. The first is a settings schema. The second is how the setting interacts with `PUSH_PROTECTED_BRANCHES` and the workflow commit checks that import `PROTECTED_BRANCHES`.
- **Scope.** This is not a bypass of the current policy, and it touches more than the safety layer.

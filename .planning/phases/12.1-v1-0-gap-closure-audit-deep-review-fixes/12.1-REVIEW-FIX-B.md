## Decisions recorded

### CR-B-01
- `gateCompletion` takes a sixth argument, `headDescendsFromBase`, so the function stays pure.
- `endRun` computes that argument with `isStrictDescendant`, which runs `git merge-base --is-ancestor base head` and requires `head !== base`. A separate commit count is not needed, because the "HEAD unmoved" branch already rejects `head === base`.
- A rebase onto another upstream now also rejects. For `/execute`, `--rebase-base` remains the way past it.

### CR-B-02
- The settle rejects when `uncommittedPaths` is non-empty, exactly as `/execute` does. A clean tree is the commit, so the gate legs that read files from disk read the committed content.
- To keep the harness's own logs from counting as dirt, `/quick` now calls `ensureHarnessIgnored` before arming. It does so silently, because a notice would change every `/quick` notification count.
- Two fixtures that planted untracked files now commit them: `quickRun`'s `cwdFiles` and the gate-order "pre-existing finding" fixture.

### CR-B-03
- **Pin.** The signed `base` row now carries `tasks: {id, path, verificationCommand}[]`.
- **Refusal.** `/execute` refuses when PLAN.md's parsed tasks differ from the pin, and so does `/review`. That covers a rewritten verification command and a deleted or added task.
- **Which command is used.** The verification command used is the pinned one, captured at arm time.
- **Re-pinning.** `--rebase-base` shows both task lists and re-pins only on approval.
- **Ledgers written before this change** have no `tasks` field. `/execute` refuses them until the user re-pins, which is fail-closed.
- **Why not a protected path.** `.pi/work/**` was not made a protected write path, because `/grill` and `/plan` have the model write SPEC.md and PLAN.md there. Detection was chosen instead. `paths.ts` is untouched.

### CR-B-04
- Surviving BLOCKERs are now checked first, and the result is never approvable. The reason also names a classification that is not `root-cause`.
- `/review`'s "Open the MR anyway?" prompt is therefore never reached while a BLOCKER survives.
- `docs/QUALITY.md` section 5 was rewritten to show the new order.

### WR-B-02 (Pi 1.1.0, verified in `node_modules`)
`sendUserMessage` catches and only reports a rejected `prompt()` (`agent-session.js:2712-2719`). `prompt()` can return before `_runAgentPrompt` in these cases (`:1517-1631`):
- no model;
- missing or expired auth;
- compaction in progress;
- an `input` handler that returns `handled`.

`before_agent_start` receives the prompt text (`types.d.ts:708-718`). `input` fires for extension-sourced prompts too.

The fix works as follows:
- `startRun` takes the prompt it sends. The run stays **pending** until a `before_agent_start` prompt contains that text.
- A pending run records no tool call, and neither settle handler ends it.
- Any other prompt that reaches `input` or `before_agent_start` first disarms the run and both workflow slots, with no verdict.
- No timer is used. A pending run is cleared by the next prompt or by `/reload`, which fires `session_start`. The shared in-flight refusal names `/reload`.
- The command handler does not auto-clear a pending run, because that would race a legitimate prompt that is still in pre-flight. The WR-01 "second /quick" test exercises exactly that window.

### WR-B-04 / WR-B-05
- `endRun` no longer writes anything. It returns the verdict plus a `RunSummary`, and each settle writes exactly one row through `writeRunEvidence` once every check has decided.
- `EvidenceRowInput.verdict` gained `"unverified"`. `/quick` uses it when no leg applies, and the notice is at `warning` level.
- `/execute` keeps its `ctx.ui.confirm` for that case. A declined prompt writes a reject row. An approved one writes an accept row whose reason says no check ran.
- An orphaned run found at `session_start` writes a reject row that says it was orphaned.
- `quick-workflow` cases 4, 6, 7, 8 and WR-01 used to commit `.txt` files and now commit `.ts` files. They test accepted runs, and a `.txt` change is now correctly `unverified`.

### WR-B-06
- ESLint runs with `--format json`. The leg reports `pass` only when at least one changed file has no "File ignored ..." message and no error-severity or fatal message.
- Exit 1 without parseable JSON still fails (fail-closed). Exit 0 without JSON is `unavailable`.

### WR-B-07
- The nearest `tsconfig.json` is parsed with the TypeScript API, which is already a runtime dependency used by `rules.ts`.
- Only a solution-style config (references, or an explicit empty `files`) with zero input files is reported `unavailable`.
- Any other config with no inputs is still left to tsc. tsc fails that case itself with TS18003, which keeps an existing test green.

### WR-B-10
`/quick` refuses to arm while the working tree is dirty and names the paths. The settle would refuse that tree anyway, after spending the run. The brief now says "staging only the files you changed (git add <path>...)".

## Decisions

- `git config` key blocking (`alias.*`, `core.sshCommand`, ...) applies to write forms only; read forms such as `git config --get remote.origin.url` stay allowed.
- Plan said `GIT_*` assignment detection; `CanonicalInvocation` gained `assignmentWords` (prefix words plus wrapper `NAME=value` words) and `ShellVerdict` gained `redirectReadTargets`.
- Glob arguments whose basename starts with a wildcard are judged by their directory part only (bash never matches a dotfile with a leading wildcard); otherwise `ls *` and `git add *` would block. Residual documented in SAFETY.md.
- New read-ish git subcommands (`check-ignore`, `notes list`, ...) are admitted on non-protected branches only. They were not added to `GIT_READ_SUBCOMMANDS` because the existing liveness test requires a row per table entry and the protected-branch behaviour (unclassified, block) is unchanged and fail-closed.
- `terraform show` / `terraform output` without a JSON/raw flag stay allowed (Terraform masks sensitive values there).
- Corpus gets a per-row `verdict` field (default block) and EV-56/EV-57 move to BLOCKED with their rows removed from the Known bypasses table. A per-row `heads` field was not needed: every BLOCKED row blocks under both HEADs.
- Existing policy-compose row `git -c user.name=x diff` changed to `-c core.quotepath=off` because `-c` is now restricted to formatting keys (plan-mandated).
- The `. git-push.sh` / `trap` cross-segment rule refuses any script that uses these builtins when a guarded verb appears anywhere in it (documented false positive: `source ./env.sh && git status`).

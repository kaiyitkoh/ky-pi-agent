## Doc deltas for Plan 10 (docs/QUALITY.md)

1. Four legs and their availability rules:
   - typecheck: runs `tsc --noEmit` only when a code file changed, a `tsconfig.json` exists at or above the cwd (up to the git top level) and the base tree did not already fail it; otherwise UNAVAILABLE. Repo-local binary, trusted projects only.
   - lint: the target repo's own ESLint on the changed code files; UNAVAILABLE without an ESLint config (`eslint.config.{js,mjs,cjs,ts}` or `.eslintrc{,.js,.cjs,.json,.yml,.yaml}`), without a repo-local `eslint`, or when the project is untrusted; exit 1 is FAIL, any other non-zero exit is UNAVAILABLE.
   - lsp: always UNAVAILABLE. A command or event context has no `executeTool` (pi-coding-agent dist/core/extensions/types.d.ts:262-280, Pi 1.1.0), so the gate cannot call `lsp_diagnostics`; registration is not a run.
   - anti-pattern: error-tier findings the base did not already have.
2. Gate-depth table: quick deterministic; grill none; plan none; execute deterministic; review deterministic, model-review, refute-or-promote. Calibration is offline-only and listed for no workflow. Refute-or-promote is implemented by `runRefuteOrPromote` (verdict.ts); `runBoundedReviewLoop` is not credited.
3. `ranAny` is true only if typecheck, lint or anti-pattern actually executed; `consult_advisor` is guarded by its real context size.

## Decisions

- Lint passes files after `--` so a file name beginning with `-` cannot be read as an ESLint flag.
- tsconfig discovery stops at the git top level (or the cwd when git cannot answer) rather than at the filesystem root.
- Lint output is bounded at 40 lines.

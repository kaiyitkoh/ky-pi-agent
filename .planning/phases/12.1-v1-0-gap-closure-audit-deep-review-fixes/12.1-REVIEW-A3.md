## Info

### IN-A3-1: Plan mode allows `bat --paging always` (the two-word spelling)

**File:** `.pi/extensions/plan-mode/read-only.ts:176`

**Issue:** The rule matches only `--paging=always`. clap also accepts the value as the next word. Probed with `classifyPlanModeCommand`:
- `bat --paging=always README.md` is denied.
- `bat --paging always README.md` is allowed.

The forced pager is the one the environment names, which is the case WR-A2-8 meant to deny.

**Fix:** match the separated form too:
```ts
bat: (args) => (args.some((a, i) => a === "--pager" || a.startsWith("--pager=") || a === "--paging=always" || (a === "--paging" && args[i + 1] === "always")) ? "`bat` runs a pager, which can run commands" : undefined),
```

### IN-A3-2: `git pull` on a protected HEAD is refused as "unclassified"

**File:** `.pi/extensions/safety/git.ts` (the protected-HEAD write table)

**Issue:** `git stash && git pull && git stash pop` blocks on `main`, and the reason reads `"git pull" is an unclassified subcommand`. Refusing is defensible, because a pull merges into the protected branch locally. However, "update main, then branch off" is a common sequence, and "unclassified" tells the model nothing.

**Fix:** either classify `pull --ff-only` on a protected HEAD as allowed (a fast-forward to the upstream does not author a commit), or name `pull` in the write table with an actionable reason ("run `git fetch` and branch from `origin/main`").

### IN-A3-3: IN-A2-2 is still open

**Status (2026-10-13):** fixed in 72f5db0 - terraform `-chdir=DIR`, `-version` and `-help` are skipped before the subcommand is classified, so `terraform -chdir=infra plan` allows and `apply` still confirms; infra rows and a corpus row added.

**File:** `.pi/extensions/safety/infra.ts`

**Issue:** `terraform -chdir=infra plan` returns `confirm` on both heads, because the global `-chdir=` option is read as the subcommand. Monorepo Terraform almost always uses this spelling, so it trains reflexive approval.

**Fix:** skip `-chdir=*`, `-help` and `-version` before reading the subcommand, as proposed in iteration 2.

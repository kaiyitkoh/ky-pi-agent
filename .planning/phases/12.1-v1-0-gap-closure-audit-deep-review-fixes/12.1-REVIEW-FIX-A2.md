## Decisions recorded

### CR-A2-1 and CR-A2-2: the code-runner rule
- **The code runners.** sh, bash, zsh, dash, ksh, mksh, ash, csh, tcsh, fish, busybox, pwsh, powershell, cmd, `python*`/py/pypy, node, deno, bun, `perl*`, `ruby*`, `php*`, `lua*`, rscript, osascript and parallel.
- **When a runner is refused.** It is refused whatever its arguments in any of these cases:
  - its stdin is a pipe (heredocs and here-strings were already refused everywhere);
  - any argument is `-`, `/dev/stdin`, `/dev/fd/N` or `/proc/<pid>/fd/N`;
  - any argument or input redirect names a file the same command wrote, whatever the file is called.
- **Accepted false positives.** `cat data.json | python script.py` (the iteration-1 negative control, now flipped) and `curl ... | python -m json.tool` are refused. The block message names the alternatives: a file argument, `< file`, or `jq`.
- **Why not narrower.** I considered a narrower rule that allows a named, pre-existing script file. It needs per-interpreter option-arity tables, which is the enumeration the orchestrator asked us to avoid.
- **Data files passed to a runner.** A data file written earlier in the same command and passed to a runner is also refused (`npm test > t.log; python parse.py t.log`). This is rare. Split the command.

### CR-A2-3 and WR-A2-6: unwrapping
- **What gets unwrapped.** `xargs` uses its own option parser, which handles bundling (`-0r`, `-n1`, `-I{}`) and the optional `-e`/`-i`/`-l` values. `find`/`fd` use the words after `-exec`/`-execdir`/`-ok`/`-okdir`/`-x`/`-X` up to `;` or `+`. `parallel` uses a small grammar.
- **Refused: the command cannot be found.** An unknown xargs or parallel option refuses (`unresolved-wrapper`).
- **Refused: the wrapped command is itself a wrapper.** This covers every `WRAPPER_GRAMMARS` entry plus xargs, parallel, find, fd, watch, and a package manager with no subcommand (`unresolved-wrapper`).
- **Refused: a wrapped code runner with inline code or a stdin alias** (`generated-script`). This includes `find -exec sh -c ...`. That form is uncommon, and the input names reach the code.
- **Unconfident wrappers.** A wrapper such as `env -x` that cannot be resolved is now refused when it reads a pipe or when one of its words names a code runner, as well as when a guarded verb appears.

### CR-A2-4: programs that take a command string
- **New cause.** `command-string-program`.
- **Prefix matching.** GNU long options accept any unambiguous prefix. tar, sort, make and rsync therefore match a prefix of the dangerous name (four characters minimum). bat (clap) matches exactly.
- **Interactive programs.** less, more, most, man, vi, vim, nvim, view, ex, vimdiff, emacs, nano, pico and gdb are refused outright, as non-interactive-unsafe.
- **git.** git's own program settings were already blocked by the git `-c` rule. EV-233 pins this.

### CR-A2-6: CDPATH and the directory stack
- **What makes the directory unknown.** Any `CDPATH` text in the command makes a relative `cd`/`pushd` target that does not start with `./` or `../` unknown. So do `pushd` with no argument, `pushd +N`/`-N`, and `popd`.
- **CDPATH from the environment is not modelled.** Treating every bare relative `cd` as unknown would make `cd sub && git commit` count as protected, which is a large false positive on a common command. Pi's shell normally has no `CDPATH`, and GitLab protection compensates. Recorded here, not published as a corpus row.

### WR-A2-4: an unresolved cd
- **What is still refused.** After an unresolved `cd`, a relative argument is refused only when it is one of these:
  - path-shaped (`.`, `/`, `\`, `~` or a glob character);
  - a credentials file name (`id_*`, `credentials`, `config`, `known_hosts`, `authorized_keys`, `environ`, `netrc`, `npmrc`);
  - a write target or a redirect;
  - the implicit `.` of a recursive search.
- **`$HOME` targets.** A `cd "$HOME/x"` target now resolves.
- **Residual.** A key file with a custom bare name read after `cd "$D"` is published as OUT-OF-SCOPE row EV-246, with a matching `docs/SAFETY.md` row.

### WR-A2-5: a protected HEAD
- **Allowed on a protected HEAD.** `checkout`, `switch` and `restore` are now named allows, and so are the stash forms `push`, `save`, `list`, `show`, `pop` and `apply`. None of them writes the branch.
- **Still checked.** A protected `-B`/`-C` target is still refused, and a later write after a switch onto a protected branch is still checked.
- **Still blocked.** `stash drop`, `clear` and `branch` stay unclassified.
- **The block reason.** It now says to run `git switch -c <new-branch>` as its own command.
- **Known false positive.** `git checkout -b feat && git commit` on `main` still blocks. HEAD is read once, and with `;` the commit could land on `main` if the checkout fails.

### WR-A2-2: writes through git, xargs and interpreters
- **git paths.** The paths of `git checkout`, `restore`, `rm` and `mv` go through the write classifier.
- **Confirmed rather than classified.** `git apply` (without `--check`, `--stat` or `--numstat`), `git am`, and `--pathspec-from-file` name their files where the guard cannot see them, so they confirm.
- **Writers under xargs or find -exec.** A writer whose operands come from the input names confirms. The input lands on `{}` or is appended to the command.
- **perl -i.** `perl -i` now writes its operands.
- **Interpreter one-liners** (`python -c`, `node -e`/`-p`, `perl -e`, `ruby -e`, `php -r`) are refused under the new cause `inline-code-effect` when the code does any of these:
  - opens a file;
  - writes;
  - imports a module by name (`require` of anything other than a `.json` file, `import(`, `__import__`, `importlib`);
  - starts a process (`subprocess`, `child_process`, `system`, `exec`, `spawn`, backticks, `qx`, `%x`);
  - uses `os.`, `fs.`, `File.`, `IO.`, dunders, `globalThis`, `Function(` or `constructor(`.
- **Still allowed.** Prints, `json.dumps`, `stdout.write` and `require('./package.json')`.
- **Stash is not path-checked.** `git stash pop`/`apply` were left out of the path check, because confirming them would add friction to `git stash && git pull && git stash pop`.

### WR-A2-8

### KNOWN-BYPASS CLASS (accepted)
- **The class.** Code the model writes with the write or edit tool (a test file, a Makefile target, a package.json script, a build config) that an ordinary command later runs (`npm test`, `make`, `pytest`) is not in any command line the guard sees.
- **Where it is published.** `docs/SAFETY.md`, "Accepted residual: code the model writes and an ordinary command runs". EV-39, EV-40, EV-94 and EV-166 are cited as instances, and the class is not enumerated.
- **Compensating controls named there:**
  - GitLab server-side protection of `main`;
  - the block-or-ask rules on protected-path writes (hooks, CI files, hook managers, rc files, extension code, agent definitions);
  - the audit log.

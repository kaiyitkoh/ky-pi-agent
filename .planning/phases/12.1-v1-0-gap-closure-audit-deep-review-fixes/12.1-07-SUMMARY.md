# Phase 12.1 Plan 07: Provider, redaction, Qoder, log-growth and template fixes Summary

Fallback no longer masks a real 429 behind a later hop's auth error, logs redact the missing credential shapes, a failed or cancelled Qoder run is reported honestly, wire rows stop growing with history, and both env templates match the code.

## Commits

- d451dc9 fix(12.1-07): fallback, redaction, fixtures out of production, honest r1 test (Task 1)
- 4f9586b fix(12.1-07): Qoder stream order, stop_reason errors, incremental fold, remote cancel (Task 2)
- 8a18f2b fix(12.1-07): bounded wire rows, prune qoder and escalation logs, rotation backoff (Task 3)
- 40d8d34 fix(12.1-07): env templates and UI git probe (Task 4)

## What changed

- `fallback.ts`: each hop is looked up and checked with `modelRegistry.hasConfiguredAuth`; skipped hops are named, the FIRST real failure (message or rejection) is what surfaces. An unresolved entry still throws when nothing has been attempted yet (loud config error), and is skipped once a hop has run. If every hop is skipped for auth, the error names them.
- `providers/schema.ts`: all `*_FIXTURES`, `ProviderErrorFixture`, `RETRYABLE_CONTROL_FIXTURE`, `ADVANCING_CLASSES` removed; fixtures now in `tests/fixtures/provider-errors.ts`. `PROSE_RETRY_FORCES_TOOL_CHOICE` deleted and the test text no longer cites it. ID text removed from fallback.ts, budget.ts and the fixtures.
- Redaction (`diagnostics/redact.ts`, `safety/audit.ts`, independent copies): JWT shape, credential-named assignments (access/refresh/session token, secret access key, client secret, snake or camel), case-insensitive bearer, `-u`/`--user user:pass`, and attached `-pPASSWORD` scoped to the mysql family (so `mkdir -p` and `find -path` survive).
- Qoder `client.ts`: stream opened before the user message; `createResultFolder` folds each frame once and joins text once; `stop_reason` other than `end_turn` throws naming it; abort cancels the stream and posts `POST /sessions/{id}/cancel` (documented at docs.qoder.com/cloud-agents/sessions.md, "Cancel Semantics"), then rejects with an `AbortError`. `index.ts` description no longer says "Phase 4/2".
- Wire: `boundRequestPayload` keeps the last `WIRE_TAIL_MESSAGES` (4) messages and adds `messageCount` and a 16-hex `messagesHash` of the full redacted array, on main and nested request rows.
- `lib/jsonl.ts`: failed live-file rename backs off 1 s, 2 s, 4 s and gives up after four failures per file while still appending; `AUXILIARY_LOG_BASES` (`qoder`, `escalation`) joins the diagnostics prune list; qoder and routing import the base constants from there.
- Templates: both files now identical, four `QODER_*` names added, vendor-exclusion text removed. `GIT_STATUS_ARGS` gains `--untracked-files=no`.

## Decisions

- The runtime hint string in `providers/schema.ts` still names `RB-03-03`: it is a user-facing message that `sso-classifier` and `bedrock-auth` tests assert, not a code comment, so it was left.
- Remote cancel uses the documented `/sessions/{id}/cancel` endpoint (confirmed against the live docs); no limit to record.
- The Qoder loopback helper gained `liveStreamOnly` and a cancel route so the late-subscribe and abort cases are expressible; the existing request-order test now expects session, stream, events.
- Stop reasons other than `end_turn` all fail (error, interrupted, retries_exhausted, requires_action); an idle frame with no `stop_reason` still passes.
- Audit's `redactSecrets` already masked camelCase keys and `aws_session_token` via its prefix-free key pattern; only JWT, `-u` and `-p` were missing there.

## Deviations from Plan

- Fallback order of preference: a first-hop failure is kept over a later hop's failure (plan wording); the existing chain test for rejections still passes.

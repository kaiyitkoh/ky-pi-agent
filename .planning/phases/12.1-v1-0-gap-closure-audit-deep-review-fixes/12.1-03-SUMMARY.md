## Decisions

- Default for an unreadable or invalid-JSON settings file when reading the prefix is the default `apac.` (the file is only read, and agent-overrides already refuses to write into a broken file).
- The planner-pin marker is only written when the pin differs from the existing `agentOverrides`; restore deletes `subagents` if it ends up empty, so the file returns byte-for-byte when written by Pi's 2-space format.
- Pin restore runs on shutdown except for `reload`, and at session start except for `reload`; after a start-time restore the pins are re-derived for the restored non-default mode so a resumed `/max` session keeps its subagent pins.
- Concurrent sessions share the settings file, so one session starting or ending removes the other's pin until its next mode switch. Documented in ROUTING.md; not solved.
- `ROUTING.md` section 3 tool-profile table and floors were stale after Plan 01 and are corrected to match `profiles.ts` (implement floor 4,179, +1,835 tokens, +78%).

## Summary

The reports are accurate: every Critical was re-derived from pinned source. The fixes are mostly small and local, but two constraints shape the plan. First, line budgets are real tests: `/quick` (`workflows/index.ts`) is at 89 of a FROZEN 100-line spec ceiling, so the `/quick` rework must live in a new `workflows/` helper module (directory budget is a ratchet that may be raised with a recorded reason; the spec ceiling may not). Second, `workflow-budgets.test.ts` demands `budget === ceil(raw/10)*10` for every directory, so each plan that grows a directory must edit that entry in the same commit; the safety directory (2722 raw lines now) will legitimately grow and should be raised once with a measured justification rather than trimmed.

Mechanism findings that change how the reports' fixes should be written: (1) unbash parses glob characters (`gi?`, `gi[t]`, `~/bin/git`) as a bare word with NO `parts`, so a "non-literal part" check on `parts` alone misses globs; the fail-closed predicate must combine a part-type allow-list with a text check. A `$'...'` ANSI-C part can also smuggle whitespace into the command name (`git$' 'push` resolves to executable `git push`). (2) pi-subagents 0.76.1 has a first-class required-child-extension registry that survives `extensions: []`, but it is a separate module root: our extension cannot `import "pi-subagents/..."`. Reach it by dynamic import of the installed file, with the `Symbol.for("pi-subagents.required-child-extensions.v1")` globalThis registry as the shared state; if registration fails, deny the `subagent` tool (fail closed). (3) Subagent children bind with `mode: "print"` and no UI context, so `ctx.hasUI === false` in every child; the RPC rule `ctx.hasUI && (mode === "tui" || mode === "rpc")` refuses children, json and print without any child detection. (4) `/execute` already enforces the D-01 half (`checkVerification` requires the latest run of exactly the declared command, exit 0, at the recorded commit, clean tree); D-01 for `/execute` is therefore a deletion (branch (3) of `gateCompletion`), and for `/quick` the "declared verification" is the change gate. (5) `agent_settled` is emitted after `agent_end` once retries/compaction/queued work are done, carries `{aborted}`, and handlers may be awaited.

**Primary recommendation:** Six sequential plans (7 with the safety split): safety parsing core, safety wiring and subagents, evidence/settle/quick, review/design-review, routing/providers/diagnostics, packaging/global install, then tests/CI/docs/traceability with the single full-suite run. Raise budgets in the same commit as the growth, with measured `why` text.

### Pattern 1: Fail-closed command-name predicate (C-1)
**What:** In `shell.ts`, replace `EXPANSION_PART_TYPES = ["SimpleExpansion","ParameterExpansion"]`-only detection for `Command.name` with an allow-list. A name is "plain" only if every part is `Literal`, `SingleQuoted`, `AnsiCQuoted` (value without whitespace) or a `DoubleQuoted` whose children are all `Literal`, AND the raw `name.text` contains none of `*?[{}~` (a word with no expansions has `parts === undefined`, so globs are only visible in text). Exempt exactly `[` and `[[` (test builtins). Anything else: new cause `non-literal-command-name` (add to `SHELL_REFUSAL_CAUSES` and `CAUSE_DETAIL`). Apply the same check to words in wrapper positions (`hasExpansionBehindWrappers`) and to `args` of a literally guarded verb (brace expansion `git push{,}` reaches a guarded verb's suffix).
**Evidence:** probe of unbash 4.0.10 [VERIFIED: executed against node_modules/unbash/dist/parser.js]:
- `{git,push} origin HEAD:main` -> name parts `[BraceExpansion]`, value `{git,push}`
- `gi? push`, `/usr/bin/gi[t] push`, `~/bin/git push` -> `{text, value}` with NO `parts`
- `$'git' push` -> `[AnsiCQuoted value "git"]`; `git$' 'push` -> parts Literal+AnsiCQuoted+Literal, `value` = `git push` (whitespace inside the executable)
- WordPart union (all types): Literal, SingleQuoted, DoubleQuoted, AnsiCQuoted, LocaleString, SimpleExpansion, ParameterExpansion, CommandExpansion, ArithmeticExpansion, ProcessSubstitution, ExtendedGlob, BraceExpansion [VERIFIED: node_modules/unbash/dist/types.d.ts:139]
- `Word.value` getter flattens non-literal parts to their `.text` (word.js:50-65), which is why `{git,push}` normalises to an executable string that matches nothing.
**Minimal change point:** `shell.ts` `hasUnresolvedExpansionInCommandPosition` / `hasExpansionPart` (lines 221-236) and `detectRefusalCause` (238-246). No change to `policy.ts` needed for C-1.

### Pattern 2: Git subcommand allow-list on every branch (C-2)
**What:** In `git.ts#classifyGitInvocation` (lines 417-473) the `if (!isProtected(facts)) return {kind:"allow"}` at line 439 is the hole. Replace with: unknown subcommand -> block on ALL branches (the protected-branch table stays for write classification). Concretely:
1. A `GIT_LOCAL_SUBCOMMANDS` allow-list (add, commit, checkout, switch, restore, branch, merge, rebase, reset, stash, tag, cherry-pick, revert, worktree, fetch, pull, clone, init, diff, log, show, status, remote, ls-files, rev-parse, blame, grep, apply, am, clean, mv, rm, describe, shortlog, reflog, bisect, submodule, gc, cat-file, ls-tree, rev-list, show-ref, for-each-ref, config READ forms only, help, version). A user alias is "unknown" and blocks. The exact list is the planner's call; fail-closed means a miss is a false positive, fixed by adding a fixture-backed row.
2. Explicit blocks (even if someone adds them to the list by mistake): `send-pack`, `subtree` with `push`, `remote-ext`, `daemon`, `http-push`, `receive-pack`, `upload-pack`.
3. `-c` / `--config-env` / `--exec-path` / `--super-prefix` / unknown global flag before the subcommand: block on every branch, unless the config key is in a tiny harmless allow-list (e.g. `core.quotepath`, `color.ui`). Rationale: `-c core.fsmonitor=...`, `core.sshCommand`, `core.pager`, `credential.helper`, `alias.*='!...'` all execute programs [ASSUMED: git semantics from training; not re-verified this session]. `toGitInvocation` (policy.ts:126-144) currently "skips only itself" for unknown flags; change to: unknown global flag -> invocation marked `unparsedGlobal` -> block.
4. `git config` / `git config --global`: allow only read forms (`--get`, `--get-all`, `--list`, `-l`, `--get-regexp`); any write, or any key matching `alias.*`, `core.(sshCommand|fsmonitor|pager|editor|hooksPath)`, `credential.*`, `include*`, `url.*`, `remote.*.(push|url|receivepack)` blocks.
5. Executables named `git-*` (`git-push`, `git-send-pack`, `git-receive-pack`): in `evaluateInvocation` normalise `git-X` to subcommand `X` and route through the same classifier (today only `executable === "git"` is handled, policy.ts:151).
6. `env`-style assignments prefixing git (`GIT_SSH_COMMAND=... git fetch`, `GIT_CONFIG_*`, `GIT_EXTERNAL_DIFF`, `GIT_PAGER`): `invocation.assignments === true` already flows into `configTrusted`; also block when any assignment name starts with `GIT_` for a non-read subcommand [ASSUMED scope].

### Pattern 6: RPC push confirm (safety/index.ts:376)

### Anti-Patterns to Avoid
- **Enumerating shell tricks.** Every new bypass in the reviews came from a construct the denylist did not name. Prefer allow-list predicates (word part types, git subcommands, agent actions).
- **Raising FEATURES_CEILINGS or the `/quick` 100-line file ceiling.** The test names this as the failure mode.
- **Silent budget bumps.** Each `why` must state the measured raw lines, the date, and the cause; the test also checks `budget === ceil(total/10)*10`.
- **Importing pi-subagents from the safety extension by bare specifier.** Separate module roots (docs/packages.md "Installed packages load with separate module roots"); importing at factory time also violates the lifecycle rule.
- **Using `agent_before_settle` to gate.** It can add a continuation; gating belongs on `agent_settled`.
- **A second safety delivery path.** Stub XOR git package, never both.

## Common Pitfalls

### Pitfall 1: Part-type check misses globs
**What goes wrong:** `gi? push` and `/usr/bin/gi[t] push` parse as a bare word with `parts === undefined` [VERIFIED: probe]; a check that walks `parts` sees nothing.
**How to avoid:** combine the part-type allow-list with a regex on `name.text`; exempt `[`/`[[` only.
**Warning signs:** corpus rows with `?`, `[`, `{` pass.

### Pitfall 2: Corpus asserts only `not allow` while HEAD is `main`
**What goes wrong:** every unclassified git form is blocked by "HEAD is protected", masking C-2/C-3 (W-7).
**How to avoid:** run git rows twice (`currentBranchFor` returns `feat` and `main`, with `gitConfigFor`/`gitBranchFor` stubs) and assert `block`, not `not allow`, for BLOCKED rows. Note `ask` is "not allow" too, so a feature-branch `git push` row asserted `not allow` passes on `ask`; use exact kinds.
**Warning signs:** a fix that makes a row pass only on `main`.

### Pitfall 3: `model_select` revert loop
**What goes wrong:** `pi.setModel(previous)` re-fires `model_select`.
**How to avoid:** reentrancy flag, ignore `source === "restore"`, never revert to a model that also fails (notify instead).

### Pitfall 4: `agent_settled` on abort
**What goes wrong:** Esc yields `aborted:true`; a naive handler records a REJECT and burns an `/execute` attempt toward `REVISION_CAP`.
**How to avoid:** disarm without a verdict when `aborted`.

### Pitfall 5: Double registration of the required extension
**What goes wrong:** the stub and the project copy both run the safety factory; the second `registerRequiredChildExtensions` throws "already registered".
**How to avoid:** catch that specific error, treat as registered.

### Pitfall 6: Frozen line ceilings
**What goes wrong:** `plan-ceremony/index.ts` is 199/200, `/quick` 89/100, `grill` 235/250. Any growth in those files fails the frozen-ceiling tests.
**How to avoid:** make edits line-neutral or move code into supporting modules (bound by directory ratchets that CAN be raised with a recorded reason).

### Pitfall 7: Comment rules
**What goes wrong:** new code carries IDs ("C-1", "D-01", "W-27") in comments; `tests/unit/comment-discipline.test.ts` fails. AGENTS.md: no history, IDs, caller references; cite external facts as one line with file:line or URL.

### Pitfall 8: Sequential, CPU-light verification
Targeted `npx vitest run <file> --maxWorkers=2` per plan; `npx tsc --noEmit` per plan; full suite once in Plan 06.

const PLAIN_PARTS = new Set(["Literal", "SingleQuoted", "AnsiCQuoted"]);
const GLOB_OR_BRACE = /[*?[\]{}~]/;
function isPlainWord(word: Word | undefined): boolean {
	if (word === undefined) return true;
	if (word.text === "[" || word.text === "[[") return true;

}

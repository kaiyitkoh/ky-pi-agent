<decisions>
Recorded here rather than asked (the user is asleep; Standing Operating Policy item 8).

- **D-A: `currentSha(cwd)` lands in `.pi/extensions/safety/git.ts`, not in a test helper.** GATE-07's
  production capture path needs a HEAD SHA at runtime, so a test-only helper would leave production
  with no reader. `safety/` is the module that already owns "ask git a question about this working
  copy" and it gains no import from anyone by hosting it (dependency direction preserved:
  `workflows/` imports `safety/`, never the reverse).
- **D-B: `currentSha` THROWS on non-zero exit; it has no sentinel.** `currentBranch` can return
  `DETACHED_HEAD` because a detached HEAD is unconditionally not-protected — a safe default exists.
  No safe default exists for "the current SHA is unknown": an unknown SHA can never legitimately
  match evidence, and returning a sentinel would let a broken repo read compare-equal to itself.
  Callers wrap it and refuse (fail closed).
- **D-C: the gate's verdict shape is `{ok:true} | {ok:false, reason}`**, matching `GuardVerdict` /
  `PlanResult` rather than safety's `{kind:"allow"|"block"}` — GATE-07 renders a verdict about a
  *claim*, which is routing's semantics, not about a command.
- **D-D: `endRun()` writes exactly one evidence row per run, and never throws**, copying
  `safety/audit.ts`'s contract for the same reason: a log-write failure must not be able to turn a
  REJECT into an unhandled exception in the caller's control flow.
</decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output → completion decision | Assistant message content is attacker-controlled for this purpose: the model can emit text that looks exactly like a passing command run |
| tool execution → evidence record | Pi's tool machinery is trusted; the model's narration of it is not |
| evidence record → `.pi/logs/*.jsonl` on a PUBLIC repo checkout | Tool input can carry secrets (a `git remote add` with a token in the URL, an `aws` command with a key) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Spoofing | `gateCompletion` | mitigate | The predicate reads only `EvidenceRecord.isError`/`.sha`, which originate from Pi's `ToolResultEvent` (`types.d.ts:691-699`), never from `message.content`. Case R1 asserts the reason contains no substring of the fabricated transcript. |
| T-06-02 | Tampering | stale-evidence reuse | mitigate | Branch (2) requires `record.sha === headSha` where `headSha` comes from a live `git rev-parse HEAD`; case R2 uses two real commits, case M1 proves a passing record at another SHA cannot be borrowed. |
| T-06-03 | Repudiation | `writeEvidenceRow` | accept | A failed row write returns `undefined` and never throws (decision D-D) — an unwritten audit is strictly better than a log failure turning a REJECT into an unhandled exception. Same disposition and rationale as `safety/audit.ts`'s T-04-15. |
| T-06-04 | Information disclosure | evidence row content | mitigate | The row is assembled field by field (never a spread); `command` is `redactString`-processed and 200-char truncated; `.pi/logs/` is gitignored and `.pi/lib/jsonl.ts` asserts the resolved path stays inside `logDir(cwd)`. No second redaction rule is written. |

| T-06-06 | Denial of service | log growth | mitigate | `EVIDENCE_ROTATE_BYTES` + `pruneEvidenceLogs` with `ownedBases` injected locally, so pruning can never delete `wire-*`, `turns-*` or `audit-*`. |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No package is installed by this plan. `package.json` is not modified; `tests/unit/pinning.test.ts`'s exactly-six-devDependencies assertion must stay green. |

<decisions>
**D-8 — The registry lives in this test file, and `docs/WORKFLOWS.md` says so.** One copy of the
numbers, in the artifact that enforces them. A committed data file plus a test would be two things to
keep in agreement for no gain; a doc table plus a test would be the drift this repo has already been
bitten by twice.

**D-9 — Discovery is the UNION of the git index and the working tree.** `extension-layout.test.ts`
scans the index because "what a consumer receives is what git committed". A budget guard needs the
opposite bias: a 1,169-line workflow file that is on disk but not yet committed must fail NOW, not at
the moment someone runs `git commit`. Filtering is by exact extension, so editor scratch files
(`*.ts.bak`, `*.swp`) are not picked up.

**D-10 — A "workflow file" is any tracked-or-present file under `.pi/extensions/workflows/**` with a
`.ts` extension, `.pi/prompts/**` with a `.md` extension, or `.pi/skills/**` with a `.md` extension.**
Pi has exactly three ways a workflow can be authored (RESEARCH.md Q2: extension, prompt template,
skill). Covering only the first would let Phase 9 dodge the budget by writing markdown — and markdown
is precisely the shape of the 1,169-line counterexample. `.pi/prompts/` and `.pi/skills/` are empty
today, so this costs nothing now and fires the day a file lands there.

**D-11 — The aggregate is a ratchet with no headroom.** `WORKFLOWS_DIR_TOTAL_BUDGET` is set to the
measured total of `.pi/extensions/workflows/**/*.ts` at commit time, rounded up to the next multiple
of ten, and the measurement date is recorded in the docstring. Growing the directory therefore
requires a deliberate edit to a committed number in the same commit as the growth — the same
discipline `docs/RUNBOOK.md` statuses already use. This is decision D-3's mechanism: shrinking
`/quick` by moving four hundred lines into a private helper raises the aggregate and fails here.
</decisions>

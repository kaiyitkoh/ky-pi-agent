<decisions>
These are the phase's load-bearing judgement calls. They are recorded here, in the plan text, because
CONTEXT.md and PATTERNS.md both name silence on them as the most likely way FLOW-01 fails at review.

**D-1 — What a "line" means: RAW lines, counted as `readFileSync(f,"utf-8").split("\n").length`.**
No comment stripping, no blank-line stripping, no parsing. Two reasons, both stated in
`docs/WORKFLOWS.md` as well: (a) a comment-excluding count means the file that ships and the file
that is measured are different artifacts — a 400-line file can pass a "40 non-comment lines" budget,
and the budget then constrains nothing a reader of the repository experiences; (b) any
comment-excluding counter is a heuristic (string literals containing `//`, block comments, JSX) and
is therefore more brittle than the thing it measures. `≤80 lines` in the ROADMAP plainly means the
lines in the file. RESEARCH.md Q2 reaches the same conclusion independently.

**D-2 — `/quick`'s file header is a deliberately short, explicitly justified exception to house
style.** PATTERNS.md measured the problem: `harness/index.ts` spends 47 of its 98 lines on its
header, and the smallest file in `.pi/extensions/` is 78 lines. House style applied unmodified
cannot fit 80. So `/quick`'s header is capped at 12 lines and says only: what the command is, that
the long-form rationale lives in `docs/WORKFLOWS.md`, and that this terseness is deliberate and is
itself the FLOW-01 constraint being honoured. The rationale is not deleted — it is relocated to a
document, which is not a workflow file and is not code. Anyone who finds the header thin is meant to
follow the pointer.

**D-3 — Against the offloading loophole (shrink `/quick` by moving 400 lines into a private
helper): the budget is enforced per file AND as a directory aggregate.** Plan 06-03 implements both.
`evidence.ts` is a legitimate separate module — it is a pure predicate with its own unit tests and it
would exist even if `/quick` did not — but "legitimate" is a judgement no test can make, so the
aggregate is what actually holds the line. Raising the aggregate requires a deliberate edit to a
committed number in the same commit as the growth, which is the same discipline this repo already
uses for runbook statuses.

**D-4 — What "routed by Phase 5" means for `/quick`, resolved (RESEARCH.md open question 1).**
`runSingleShotRole` throws for the `executor` role by design (`modes.ts:401-406`), so `/quick` does
NOT make a nested model call. `/quick` calls `planRoleCall(ctx.modelRegistry, {role:"executor",
state: getModeState(), need: {}})` as a **pre-flight**: it resolves the current mode's executor
route, picks a configured candidate, and runs the capability guard — and refuses, verbatim, if any
of that fails. Only if the route is servable does it hand the task to the session's ordinary prompt
loop via `pi.sendUserMessage`. This is provable by a test in exactly the way the phase demands: an
unservable route must produce `/quick`'s refusal carrying `pickConfiguredCandidate`/`guardRoute`'s
own reason string, with **zero provider requests made** — a hardcoded refusal cannot produce the
router's wording, and a hardcoded allow cannot produce zero requests.

**D-5 — "logged by Phase 2" needs no code in `/quick`.** Because the work turn is the ordinary
session prompt loop, the diagnostics extension's own `turn_end` handler writes the turn row for it.
`/quick` does not call `callModel` and does not widen `CallModelOptions`. Plan 06-04 proves this by
loading diagnostics alongside and asserting the turn row exists.

**D-6 — The gate fires on `agent_end`, not on an awaited `waitForIdle`.** See the MEASURED
CONSTRAINT above: `waitForIdle` is a resolve-immediately no-op in every headless session, so a
`/quick` that awaited it would evaluate the gate before the model had done anything and would look
correct while proving nothing. `agent_end` is a real Pi event that fires in headless sessions
(measured in Phase 2, plan 02-07: `before_agent_start`, `turn_start`, `before_provider_headers`,
`agent_end` all fire after the first prompt).

**D-7 — `/quick` reads git but never mutates it.** The only git calls in this file are
`currentBranch(ctx.cwd)` and `currentSha(ctx.cwd)`, both read-only, both `shell:false` with fixed
argv. The commit is made by the model calling the bash tool, which is where Phase 4's wrapper
enforces policy for real. The `classifyGitInvocation` pre-flight is not a substitute for that
enforcement — it exists so `/quick` refuses on `main` before burning a turn, and `tests/integration/
double-enforcement.test.ts` already covers the case where the two layers disagree.
</decisions>

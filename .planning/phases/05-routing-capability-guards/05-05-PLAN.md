Create `.pi/extensions/routing/agent-overrides.ts`. Named exports only, no default export.

**Decision taken here, resolving RESEARCH Assumption A1 (one line, per the standing policy —
do not defer and do not ask): the write target is the GLOBAL agent settings file,
`join(getAgentDir(), "settings.json")`.** Three reasons, to be written into the docstring:
`.pi/settings.json` is tracked in this public repository at `{}`, so a project-scoped write
would dirty the working tree on every `/cheap`; `bin/bootstrap.sh#merge_settings` already
established `$PI_AGENT_DIR/settings.json` as this project's settings write target, and one
location beats two; and SAFE-11 already established that subagent-visible configuration
belongs at user scope, because subagents spawn headless and never grant project trust.
`getAgentDir` is exported from `@earendil-works/pi-coding-agent` (`dist/index.d.ts:2`) and
honours `PI_CODING_AGENT_DIR`, which is also what makes this testable against a temp dir.

Export:
- `agentOverridesFor(state: KyModeData): Record<string, { model: string }>` — pure. For every role whose `ROLE_MECHANISM` is `"subagent"`, emit `AGENT_NAME_BY_ROLE[role] -> { model: "<provider>/<id>" }` using the FIRST candidate of that role's route under the given state. Explicit pins only: subagents inherit the parent model when unpinned (ARCHITECTURE:400), which is exactly the half-swapped map this requirement exists to prevent.
- `resolveSettingsPath(opts?: { settingsPath?: string }): string` — the injected path when given, otherwise `join(getAgentDir(), "settings.json")`. The seam exists for tests; production never passes it.
- `writeAgentOverrides(overrides, opts?): { ok: true; written: boolean; path: string } | { ok: false; reason: string; path: string }` — the read-modify-write.

Port `merge_settings`'s validation exactly, preserving its three load-bearing properties:
1. missing file or empty file → treat as `{}`; invalid JSON → **refuse** with a reason naming the path and the parse error, never truncate, never overwrite;
2. parsed value that is `null`, an array or a non-object → **refuse** with a reason, never coerce;
3. replace ONLY `obj.subagents.agentOverrides`. Create `obj.subagents` if absent, but if `obj.subagents` exists and is not a plain object, refuse. Every sibling key (`kyPiAgent`, any `subagents.defaultModel`, anything the user wrote) survives untouched.
Serialise with `JSON.stringify(obj, null, 2) + "\n"` to match `merge_settings`' byte shape, and
**skip the write entirely when the resulting text is byte-identical to what is already on
disk**, returning `written: false`. A settings file whose mtime changes on every command is
noise that hides real changes.

`writeAgentOverrides` returns a refusal rather than throwing, so a mode command can report
"the model switched but the subagent pins did not, because <reason>" instead of failing the
whole switch or — worse — silently succeeding.

Docstring: PURPOSE, the global-vs-project decision with its three reasons, the exact shape
written, and a **PHASE 7 RE-VERIFICATION** section: this shape
(`{ "<agentName>": { "model": "<provider>/<id>" } }`) is ARCHITECTURE.md's documented
precedence-chain shape and a forward-compatible best guess — `pi-subagents` is not installed
yet, and EXT-08 requires every pin to be re-verified at Phase 7 planning time. Name that
explicitly so Phase 7 checks it instead of inheriting it.

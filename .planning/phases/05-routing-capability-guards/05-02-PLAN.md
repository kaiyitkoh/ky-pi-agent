`diagnostics/` or `providers/`. Type-only import of `Api`/`Model` from

Export:
- `type GuardVerdict = { ok: true } | { ok: false; reason: string }`
- `interface GuardNeed { image?: boolean; estimatedInputTokens?: number; thinkingRequested?: boolean; usesToolLoop?: boolean }`
- `function guardRoute(model: Model<Api>, role: string, need: GuardNeed): GuardVerdict`
- `function isAnthropicClaudeModel(model: Model<Api>): boolean`
- `const NO_TOOL_CALLING_MODEL_IDS: readonly string[]`

The four blocks, in this order, each returning a reason that names the model as
`${model.provider}/${model.id}` and the concrete numbers involved:

1. **Image → text-only** (ROUTE-06): `need.image === true && !model.input.includes("image")`. The reason must include the actual `input` array. Both daily-driver DashScope models are `["text"]`, so this fires on the realistic configuration.
2. **Oversized context → small window** (ROUTE-06): `need.estimatedInputTokens > model.contextWindow`. Reason names both numbers.
3. **Bedrock non-Claude + thinking** (ROUTE-07): `model.provider === "amazon-bedrock" && model.reasoning === true && !isAnthropicClaudeModel(model) && need.thinkingRequested === true`. The reason must state that the configuration is DROPPED SILENTLY, not rejected by the vendor, and cite `bedrock-converse-stream.js:889-927`.
4. **No tool calling** (ROUTE-08): the model id matched case-insensitively against `NO_TOOL_CALLING_MODEL_IDS = ["deepseek.r1-v1:0", "us.deepseek.r1-v1:0"]`, applied when the role uses a tool loop.

**ROUTE-08 is a deny-list, and the comment beside it must say why in plain words.**
`Model<TApi>` (pi-ai `dist/types.d.ts:661-682`) carries `id`, `name`, `api`, `provider`,
`baseUrl`, `reasoning`, `thinkingLevelMap`, `input`, `cost`, `contextWindow`, `maxTokens`,
`samplingParams`, `headers`, `compat` — and **no field anywhere expresses tool-calling
support**. There is no catalogue predicate to write. A future reader who assumes a flag
exists will "simplify" this list into a bug, so the comment states the absence explicitly
and names the verification date and source.

**Decision taken here, resolving RESEARCH Open Question 1 (do not defer, do not ask):** the
no-tool-calling block applies when `need.usesToolLoop === true`, and the caller sets that
from `ROLE_MECHANISM` — `true` for `set-model` (executor) and `subagent` (planner) roles,
`false` for a single-shot `call-model` role that passes no tools. This matches ROUTE-08's own
wording ("as an executor") and the underlying defect precisely: R1 has no defect for a
tool-less completion, and over-blocking a technically-fine use is its own silent-degradation
failure. Write that decision as a comment in the file.

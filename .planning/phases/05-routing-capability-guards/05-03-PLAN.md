<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model-supplied `task` parameter → outbound HTTPS request | Untrusted model output crosses a network boundary carrying a bearer credential |
| `QODER_PERSONAL_ACCESS_TOKEN` (env) → HTTP header → any transcript | A live credential in a tool path inside a PUBLIC repository |
| `api.qoder.com` SSE body → parser | Untrusted network input parsed in-process |
| delegated task → Qoder's own agent loop | Work performed entirely outside this harness's controls, on a laptop where merging to `main` auto-deploys to AWS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-08 | Information Disclosure | PAT leakage into a committed file or a transcript | mitigate | Env-only read at ONE call site (`index.ts#execute`); `client.ts` never reads `process.env` (asserted by grep); the `Authorization` value is never placed in a record at all; every transcript record passes `diagnostics/redact.ts#redactDeep` and is written only under gitignored `.pi/logs/` via `.pi/lib/jsonl.ts` |
| T-05-09 | Elevation of Privilege | confused deputy — Qoder performs an action the Phase 4 guard would have blocked | accept (cannot be technically prevented) | Qoder's environment is opaque by design. Mitigation is disclosure: the tool description names all four bypassed controls and the auto-deploy consequence, so both the model and the user see it before invocation; the full statement lands in `docs/ROUTING.md` (plan 05-12). Residual risk is stated, not hidden |
| T-05-10 | Tampering / Denial of Service | malformed or adversarial SSE payload | mitigate | Per-line `JSON.parse` in try/catch, unknown event types ignored, no `eval`, no dynamic code construction from payload; termination only on an explicit `session.status_idle` or connection close/timeout |
| T-05-11 | Spoofing | a test or copy-paste aiming the client at a live host, or at a non-TLS host | mitigate | The base URL seam accepts only `https:` or a `127.0.0.1` loopback URL, enforced in the client rather than at the call site — `tests/helpers/loopback.ts:59-71`'s own discipline |

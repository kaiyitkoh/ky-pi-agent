  <action>
Create `tests/helpers/qoder-loopback.ts`, modelled on `tests/helpers/loopback.ts` but shaped
for Qoder's envelope rather than OpenAI completions SSE — RESEARCH A.8 states explicitly that
`defaultSseBody` is the wrong shape to reuse. Zero dependencies: `node:http` only.

Export `withQoderLoopback(opts, fn)`: binds a server on `127.0.0.1` (port 0), hands the
callback `{ baseUrl, received }`, and closes the server in a `finally` so a failing assertion
cannot leak a listener. It must:
- route `POST /sessions` → a JSON session object with an id, `type:"session"`, `status:"idle"`;
- route `POST /sessions/{id}/events` → a 2xx ack;
- route `GET /sessions/{id}/events/stream` → `text/event-stream` writing the frames the test
  supplies, defaulting to the RESEARCH C.3 sample (an `agent.thinking` `event_start`, an
  `agent.message` `event_start`, one or more `event_delta` frames, and a terminal
  `session.status_idle` with `stop_reason.type === "end_turn"`);
- record every request as `{ method, url, headers, body }` on `received`, so the test asserts
  on what the client ACTUALLY sent rather than on what it believes it sends;
- support options for the frame script, an injected delay/chunk-boundary split (so a frame can
  be delivered split across two writes), an arbitrary extra frame with an UNKNOWN event type,
  and a non-2xx status on any of the three endpoints.

Export `assertQoderLoopbackUrl(url)` following `loopback.ts`'s discipline exactly: it throws
unless the host is `127.0.0.1`, the literal is written out independently of the bind call
(two literals cannot agree by accident), and the comment states that the check lives here
rather than at the call site so a copy-paste that reintroduces a real host fails loudly
instead of quietly issuing a live request from CI.

This helper is test-only and lives under `tests/`, so no extension-layout or chokepoint rule
applies to it — but keep it dependency-free anyway, matching `loopback.ts`'s stated
discipline.
  </action>

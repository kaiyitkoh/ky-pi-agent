<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted session entry → module state on restore | Data read back from a session file drives which model serves the session |
| persisted payload → LLM context | The whole zero-token claim rests on this boundary NOT being crossed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-36 | Tampering | a hand-edited or corrupted `ky:mode` payload | mitigate | The payload's `mode` is validated against `MODES` before use and falls back to `DEFAULT_MODE`; the whole handler is wrapped so a malformed branch cannot prevent a session from starting |
| T-05-37 | Information Disclosure | routing state leaking into provider requests | mitigate | Asserted by absence across every captured outgoing payload, with a positive control proving the capture is live — not by quoting Pi's doc comment |
| T-05-38 | Spoofing | two sources of truth for the executor model | mitigate | The hook restores mode/escalation ONLY; Pi's own `model_change` entry remains the sole authority for the model, and the test asserts that entry exists so a regression upstream is visible |
| T-05-39 | Denial of Service | a restore failure blocking session start | mitigate | try/catch around the handler, following `safety/index.ts:832-838`'s established posture |
</threat_model>

### `tests/helpers/faux.ts` (test helper, transform) - UPG-02

**Analog:** itself. Change only the context type and the readers; keep everything else, including both wrapper bodies written out twice (acceptance greps depend on that, see docstring L299-302 and L369-372).

**Current type import to change** (L83-90): `Context` becomes `TranscriptContext`; add `getCurrentSystemPrompt`, `getCurrentTools` as VALUE imports from `@earendil-works/pi-ai` (this file currently has type-only imports).
```typescript
import type { Context, FauxProviderHandle, Message, Model, Provider, StreamOptions } from "@earendil-works/pi-ai";
export type FixturePayloadBuilder = (model: Model<string>, context: Context, options: unknown) => unknown;   // L101-105
```

**Core pattern to rewrite** (`buildOpenAiFixturePayload`, L175-204). Today reads `context.systemPrompt`, `context.messages`, `context.tools`:
```typescript
const messages: { role: string; content: unknown }[] = [];
if (context.systemPrompt) { messages.push({ role: "system", content: context.systemPrompt }); }
for (const message of context.messages) { messages.push({ role: message.role, content: messageContent(message) }); }
...
if (context.tools && context.tools.length > 0) { payload.tools = context.tools.map(...) }
```
Replacement (RESEARCH Pattern 1): `const systemPrompt = getCurrentSystemPrompt(context.messages); const tools = getCurrentTools(context.messages);` and iterate only `m.role !== "system"` messages (a `system` message in `messages` would otherwise be emitted twice). `messageContent(message: Message)` (L141-160) reads `message.content` and will not accept the new `system` role cleanly; narrow with `Exclude<Message, { role: "system" }>`.

**Bedrock builder** (L242-279): same swap at `messages:` (L259), `system:` (L263) and `toolConfig` (L265-276).

**Do not change:** `wrapFauxWithPayload` / `wrapFauxWithStatus` bodies except the `context` parameter type (inferred from `Provider`). Re-verify the `onResponse` hard-coded-200 claim (docstring L70-71, L329) against 1.1.0 `faux.js` before trusting `tests/unit/helpers.test.ts` invocation-count-exactly-1 assertion.

**Pitfall (tsc is green, runtime is red):** `TranscriptContext` is structurally assignable to `Context`; a builder left on `Context` compiles and sees `undefined`. Add a unit assertion in `tests/unit/helpers.test.ts` that a captured context yields a non-empty `getCurrentSystemPrompt`.

**Consumers of the response-factory `context` param** (same fix: use accessors, not `.systemPrompt`/`.tools`): `tests/integration/double-enforcement.test.ts:133-148` (`capturing(into: Context[], ...)`, `lastToolResult(context: Context)` read only `.messages`, so they keep working but should be retyped to `TranscriptContext`), plus the files in the RESEARCH edit table (`budget.test.ts` ~117/185-215/236, `reviewer-contract.test.ts` 385-400, `wire-capture.test.ts` 232-236 drop the `+1` double count).

- **[Rule 3] Tasks 1 and 2 committed together.** PROVENANCE was written in full once the trim was complete, so splitting the commit would have meant a half-written record.
- **[Rule 3] `tests/unit/tool-count-baseline.test.ts`:** `extractRegisteredToolNames` matched only double-quoted `name:`; the vendored source is single-quoted, so the regex now accepts both. Direction 4 (npm "eleven tools" handoff checks) was rewritten to assert the four-tool vendored row.
- **[Rule 3] Registry side effects not in the plan's file list:** `contributing-boundary.test.ts` (tool-registration allowlist entry with the (a)/(b)/(c) answers) and `workflow-budgets.test.ts` (per-file and directory budgets: 990 / 10350, re-measured by the test's own counter).
- **PROVENANCE wording:** avoided the literal package name `pi-subagents` in the text, because `extension-pins` Direction 3 treats any PROVENANCE mention of an installed package name as vendored-and-installed.
- Extensions wrapper `extensions/background-tasks.ts` not vendored (index.ts is the sole default export, BOOT-05).
- Case A's tool list is read through the session tool allowlist (`getAllTools` is filtered by it); the allowlist includes the dropped names so their absence is meaningful.

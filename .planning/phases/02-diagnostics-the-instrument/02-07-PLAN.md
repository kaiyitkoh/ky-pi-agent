Create `.pi/extensions/diagnostics/call-model.ts` exporting the chokepoint exactly as RESEARCH §4.6 specifies.

Export `interface CallModelOptions<TApi extends Api>` with: `role: string` (mandatory — it is the join key between the wire log and the turns log, and the field that makes "was `/max` worth it?" answerable); `model: Model<TApi>`; optional `systemPrompt`; `messages: Message[]`; optional `tools`; optional `api` typed as `Omit<ModelsApiStreamOptions<TApi>, "onPayload" | "onResponse" | "transformHeaders" | "signal">`; and optional `signal` defaulting to `ctx.signal` so Esc cancels nested work.

Export `async function callModel<TApi extends Api>(ctx: ExtensionContext, opts: CallModelOptions<TApi>): Promise<AssistantMessage>`. Its body:
- record `started = Date.now()` and issue `corr = nextCorrelationId(sessionId)`;
- call `ctx.modelRegistry.complete(opts.model, { systemPrompt, messages, tools }, options)` where `options` spreads `opts.api`, sets `signal` and `sessionId`, and supplies all three capture callbacks:
  - `transformHeaders` appends a `nested.headers` wire record with `redactHeaders(h)` and **returns `h` unchanged** — it is a transform, and returning anything else would alter the real request;
  - `onPayload` appends a `nested.request` wire record with `redactDeep(p)` and **returns `undefined`**, keeping the payload;
  - `onResponse` records the status into a local and appends a `nested.response` wire record;
- wrap the whole call in `try`/`catch`/`finally` so that a thrown provider error still produces a turns row: on catch, compose a row from a synthesised error-shaped message carrying `stopReason: "error"` and the redacted error text, append it, and rethrow — the caller decides what to do, but the measurement is never lost;
- on success call `composeTurnRow` with `kind: "nested"`, `role`, `corr`, `latencyMs`, `httpStatus` and the returned message, and append it to the turns stream;
- return the `AssistantMessage`.

Docstring in the `tests/helpers/git.ts` shape, with three named sections:
- **The rule.** This is the only file in the repository permitted to reach the model API directly. Every other model invocation goes through this function, and `tests/unit/chokepoint-lint.test.ts` fails the build otherwise.
- **The verified trap.** Extension hooks are blind here: a nested `complete()` fires none of `before_provider_headers`, `before_provider_request` or `after_provider_response` — executed 2026-08-13, the logging extension's file was never created (RESEARCH §4.4). The three per-call callbacks are the complete replacement. `calculateCost` is applied defensively because faux returns all zeros and real adapters have already done it idempotently.
- **Scope caveat, stated rather than overclaimed.** Name the bypass routes the gate cannot close: `modelRegistry.getProvider(id)` and `getRegisteredNativeProvider(name)` return a `Provider` whose `.stream()` bypasses everything; `ModelRuntime` is a public export; `@earendil-works/pi-ai` exposes `./api/*` subpaths so an adapter's `stream` can be imported outright; string-built property access, a destructured-then-renamed registry and `eval` defeat any grep; and a composed third-party extension (Phase 7) is not under `.pi/extensions/` at all. This is the same honest-limits posture SAFE-15 requires of the bash guard.

The file must not contain the substring `registerTool`.

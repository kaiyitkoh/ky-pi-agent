  <action>
Create `.pi/extensions/diagnostics/budget.ts`.

Export `estimateTokensFromChars(chars: number): number` returning `Math.ceil(chars / 4)`, with a docstring stating this is Pi's own heuristic (`compaction.ts:274`), that it is an estimate with roughly ±20% error, that no tokenizer exists in either Pi package and none may be added, and that the provider-reported `usage.input` is shown beside it as ground truth.

Export `sliceSystemPrompt(prompt: string): { total: number; base: number; contextFiles: number; skills: number; contextFilesFound: boolean; skillsFound: boolean }`. Locate the context-file block by its literal delimiters `<project_context>` and `</project_context>` and the skills block by the literal opening sentence `The following skills provide specialized instructions`, both transcribed from the cited sources. `base` is `total` minus the located sections. When a marker is absent, set the corresponding size to 0 and the corresponding `*Found` flag to `false` rather than guessing — a silent 0 and an absent marker must be distinguishable, because a marker change in a future Pi release is exactly the failure this decomposition would otherwise hide.

Export `interface BudgetInput` with `systemPrompt: string`, `contextFiles: readonly { path: string; content: string }[]`, `skills: readonly unknown[]`, `skillsBlock: string | undefined` (the result of `formatSkillsForPrompt`, supplied by the caller so this module stays pure), `tools: readonly { name: string; description: string; parameters: unknown }[]`, `lastUsage: { input: number; cacheRead: number } | undefined`, and `rowsWritten: number`.

Export `computeBudget(input: BudgetInput): BudgetReport` returning a structured report with, for each section, both a character count and an estimated token count: system prompt total, base prompt, context files (also broken down per file path), skills index, and tool schemas (summing `name.length + description.length + JSON.stringify(parameters).length` over the supplied tools, with a per-tool breakdown so the most expensive tool is nameable). Include `cacheRead` and `input` from `lastUsage` when present, the derived cache-read ratio, `rowsWritten`, and a `skillsBlockMatchesSlice` boolean computed by comparing the recomputed `skillsBlock` length against the sliced skills length. Include `warnings: string[]` carrying a message when a marker was not found and when `skillsBlockMatchesSlice` is false — the RESEARCH instruction is that a divergence means Pi changed the format and `/budget` should say so loudly rather than silently mis-report.

Export `formatBudgetReport(report: BudgetReport): string` producing plain aligned text. Characters are the primary figure; every token number is suffixed with an explicit estimate marker such as `~` plus the note that it is a ±20% estimate; the provider-reported `input` and `cacheRead` are printed on their own line labelled as provider-reported ground truth; and a final line prints the rows written this session with a note that 0 means the instrument recorded nothing.

Export `registerBudgetCommand(pi: ExtensionAPI, rowsWritten: () => number): void` registering a command named `budget` with a one-line description. Its handler pulls `ctx.getSystemPrompt()`, `ctx.getSystemPromptOptions()` (command context only), computes `formatSkillsForPrompt(opts.skills ?? [])`, filters `pi.getAllTools()` by the set from `pi.getActiveTools()`, reads the last assistant usage via the exported `getLastAssistantUsage(ctx.sessionManager.getBranch())`, calls `computeBudget` and `formatBudgetReport`, and writes the result to the UI. Wrap the whole handler body in `try`/`catch`; on catch, surface the error through the UI **and** append a `diagnostics.error` row, so a broken report is visible in both places.

Module docstring stating the BOUNDARY RULE inline: this is a command and never a tool, because a tool's JSON Schema rides in every request payload — and this file therefore does not name the tool-registration call even in prose. Add a second reason from RESEARCH §7.1: `getSystemPromptOptions()` exists only on the command context, so a tool could not compute this report at all.

The file must not contain the substring `registerTool`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| system prompt content → report output | The system prompt contains this project's `CLAUDE.md`, which is public, but a user's global context file may not be |
| Pi's prompt format → the decomposition | The slicer depends on literal markers in a package that ships every 2–3 days |
| new capability → per-request token cost | Anything registered as a tool rides in every request payload |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10-01 | Information Disclosure | `/budget` printing context-file *content* rather than sizes | mitigate | The report prints paths and character counts only; no content is emitted, and no report is written to disk |
| T-02-10-02 | Repudiation | a marker change silently mis-attributing the whole prompt to `base` | mitigate | `contextFilesFound` and `skillsFound` flags plus a `warnings` array; the skills slice is cross-checked against the exported `formatSkillsForPrompt`; the integration test asserts against the installed Pi version |
| T-02-10-03 | Repudiation | a token figure read as exact | mitigate | Characters are the primary figure; every token number carries an explicit estimate marker; the provider-reported `usage.input` prints beside it as ground truth |
| T-02-10-04 | Repudiation | a silently dead instrument reporting nothing while appearing healthy | mitigate | `/budget` prints rows written this session; the zero case is asserted in the unit test |

| T-02-10-06 | Repudiation | a `/budget` handler exception vanishing | mitigate | The handler body is wrapped in `try`/`catch` that surfaces to the UI and appends a `diagnostics.error` row |
| T-02-10-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs nothing. A tokenizer is explicitly rejected (RESEARCH §7.2: neither Pi package depends on one, and `tests/unit/pinning.test.ts:253` fails the build if a dependency is added) |

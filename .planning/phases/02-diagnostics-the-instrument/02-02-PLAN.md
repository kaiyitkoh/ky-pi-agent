  <action>
Create `.pi/extensions/diagnostics/redact.ts` as a pure module with no imports beyond types.

Export `redactionPlaceholder(length: number): string` returning the literal form `[redacted:<n> chars]`. Keeping the length makes "was a credential present at all?" answerable without exposing it.

Export `REDACTED_HEADER_KEYS: readonly string[]` containing, lower-cased: `authorization`, `x-api-key`, `api-key`, `cf-aig-authorization`, `x-goog-api-key`, `proxy-authorization`, `cookie`, `set-cookie`. Export `REDACTED_HEADER_KEY_RE` as `/(^|[-_])(api[-_]?key|token|secret|credential|password)([-_]|$)/i`. A header key is redacted when its lower-cased form is in the list or matches the regex.

Export `SECRET_VALUE_PATTERNS: readonly RegExp[]` implementing exactly the RESEARCH §1.3 set: an `sk-` prefixed run of 16 or more token characters; `AKIA` followed by 16 upper-alphanumerics; `ASIA` followed by 16 upper-alphanumerics; the GitHub prefixes `ghp_`, `gho_`, `ghu_`, `ghs_`, `github_pat_`; the Slack prefixes `xoxb-` and `xoxp-`; `AIza` followed by 35 token characters; `pt-` followed by 16 or more alphanumerics (Qoder PAT); a PEM header of the form `-----BEGIN <upper words> PRIVATE KEY-----`; `Bearer` plus whitespace plus 20 or more token characters; and `aws_secret_access_key` followed by optional whitespace, `=`, optional whitespace and a non-whitespace run. Every pattern must be **bounded** — no unanchored `.*`, no nested quantifier that can backtrack catastrophically. Add a comment naming ReDoS as the reason and citing the Security Domain row.

Export `redactString(value: string): string` which replaces every match of every pattern with `redactionPlaceholder(match.length)`, leaving all other characters untouched.

Export `redactHeaders(headers: Record<string, string | null>): Record<string, string | null>` which returns a new object where a redacted key's non-null value becomes `redactionPlaceholder(value.length)`, a `null` value stays `null`, and a non-redacted key's value still goes through `redactString`.

Export `redactDeep<T>(value: T): T` which walks strings, arrays and plain objects, applying `redactString` to every string leaf and `redactHeaders`-style key matching to object keys whose name matches the header rule. Guard the walk with a depth cap of 24 and a node budget of 200_000 nodes; on exceeding either, return the literal string `"[redacted:truncated]"` for that subtree and record nothing else. Numbers, booleans, `null` and `undefined` pass through unchanged. Document that returning a *new* structure rather than mutating in place is required because `before_provider_request` must not alter the payload the provider receives.

Write the module docstring in the `win-quote.ts` shape, with these headings and content: why redaction happens at capture and not at read (a live key on disk in a public repo is a breach even if a later reader would have masked it); why key-name matching alone is insufficient (the payload never carries the API key — RESEARCH §1.3 — so the real hazard is a `.env`, `~/.aws/credentials` or `*.tfstate` the model read into `messages[]`, and Phase 4's read-block has not shipped); and the scope caveat, stated rather than overclaimed: this list is a judgement call recorded as Assumption A2, a missed pattern is a credential on disk, and `RB-02-02` is the real grep over real dumps.

The file must not contain the substring `registerTool` anywhere, comments included.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model context → captured payload | Untrusted file contents the model read (`.env`, `~/.aws/credentials`, `*.tfstate`) cross into `messages[]` and then into a dump |
| resolved provider auth → `before_provider_headers` | Live bearer tokens and API keys cross into a hook that this phase logs |
| dump on disk → public GitHub repo | Anything written under the working tree is one `git add -f` away from being published |
| untrusted model output → regex engine | An assistant message of arbitrary size is fed to the pattern set |

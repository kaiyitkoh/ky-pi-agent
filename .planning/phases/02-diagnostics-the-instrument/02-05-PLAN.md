<objective>
Capture the wire: register the three provider hooks on the main agent loop, redact
at capture, and append to `.pi/logs/wire-<date>.jsonl`.

Purpose: ROADMAP success criterion 1 — "for any model invocation the user can read
the exact JSON that went on the wire, with credentials redacted at capture time and
dumps written only to gitignored paths". Two contracts are load-bearing and both are
easy to get silently wrong: a `before_provider_request` handler that returns
anything non-`undefined` silently replaces every request payload
(`runner.ts:1031-1033`), and a plain `fauxProvider` never fires the hook at all, so
a naive test is vacuously green.

Output: `wire.ts`, its registration in `index.ts`, the handler-return unit test, and
the live-session integration test that reads the on-disk bytes.
</objective>

Create `.pi/extensions/diagnostics/wire.ts`.

Export a monotonic correlation counter: `nextCorrelationId(sessionId: string): string` producing a value of the form `<sessionId>#<n>` with `n` incrementing per process, and `currentCorrelationId(): string | undefined` returning the last issued value. Document why the id is maintained here rather than derived from a hook: `before_provider_headers` fires once per logical request and provider-level retries reuse the same headers without re-firing (`docs/extensions.md:676`), so per-attempt correlation is not observable on the main loop and must not be claimed.

Export `wireRecord(kind: WireRecord["kind"], fields: Partial<WireRecord>): WireRecord` — a pure composer stamping `ts` and `corr`, used by both this file and `call-model.ts`.

Export `registerWireHooks(pi: ExtensionAPI, safeHandler: SafeHandlerFactory): void`. It registers exactly three hooks, each with a **block body and no return statement anywhere in the handler**, each wrapped by the caller-supplied `safeHandler`:

- `before_provider_headers` — issues a new correlation id keyed on `ctx.sessionManager.getSessionId()`, then appends a `main.headers` record whose `headers` field is `redactHeaders(event.headers)`. Mutate nothing; the return value is ignored by Pi but the handler still must not return a value, so the shape stays identical to the other two.
- `before_provider_request` — appends a `main.request` record whose `payload` field is `redactDeep(event.payload)`. Add a comment directly above the closing brace stating: NO return. A non-`undefined` return replaces the payload for later handlers and for the actual request (`runner.ts:1031-1033`), so an arrow function with an expression body here would silently rewrite every request.
- `after_provider_response` — appends a `main.response` record carrying `status` and `headers` (headers passed through `redactHeaders`). Add a comment stating that this hook never fires on a provider error (`openai-completions.ts:239` versus the catch at `:590`), so no field of the turns row may be derived from it — it contributes an optional `httpStatus` only.

All three append through `appendJsonl(ctx.cwd, WIRE_LOG_BASE, record, { rotateBytes: WIRE_ROTATE_BYTES, maxRotated: MAX_ROTATED_FILES })` and increment the rows-written counter.

Module docstring stating: the source is Pi's bundled `examples/extensions/provider-payload.ts`, and the deltas this file adds are redaction at capture, rotation, a per-handler `try/catch`, and a correlation id. Add a **Known limits** paragraph naming the Bedrock gap verbatim in substance: SigV4 is applied by Smithy middleware downstream of anything Pi hands over, and `x-amz-*`, `authorization` and `host` are silently ignored on that path (`pi-ai types.ts:148-153`), so the inspector never sees a Bedrock credential in `before_provider_headers` — recording that as a limitation is more honest than implying the dump is complete.

The file must not contain the substring `registerTool`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| resolved provider auth headers → capture hook | Live bearer tokens and API keys cross into a hook whose whole job is to write them down |
| model context (`messages[]`) → capture hook | Any file the model read this session, including `.env`, `~/.aws/credentials` and `*.tfstate`, crosses here |
| capture handler → outgoing request | A non-`undefined` return replaces the real request payload |
| wire dump → public GitHub repo | The dump lives inside the working tree |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05-01 | Information Disclosure | a credential surviving into `wire-<date>.jsonl` | mitigate | `redactDeep` on every payload and `redactHeaders` on every header set, applied synchronously before `appendJsonl`; case 3 reads the on-disk bytes and asserts the plaintext is absent |
| T-02-05-02 | Information Disclosure | a Bedrock SigV4 credential silently never appearing, making the redactor's Bedrock path untested | accept | Structurally impossible to capture (`pi-ai types.ts:148-153`); recorded as a Known limits paragraph in `wire.ts` and re-stated in `docs/DIAGNOSTICS.md` (plan 02-11); `RB-02-02` is written around the DeepSeek/DashScope bearer path instead |
| T-02-05-03 | Tampering | a capture handler silently rewriting every request payload | mitigate | Block-bodied handlers with no value return; `tests/unit/wire-nonmutating.test.ts` asserts `undefined` and payload round-trip equality; the expression-bodied form is verified to break the suite |
| T-02-05-04 | Information Disclosure | the dump landing on a non-gitignored path | mitigate | Path built only from `ctx.cwd` + `CONFIG_DIR_NAME`; case 5 runs `git check-ignore -q --no-index` over the paths actually produced |
| T-02-05-05 | Repudiation | a capture failure disappearing into `emitError` | mitigate | Every hook wrapped in `safeHandler`, which writes a `diagnostics.error` row; the unit test forces a throwing append and asserts no propagation |
| T-02-05-06 | Denial of Service | wire records at ~50 KB each filling the disk | mitigate | `WIRE_ROTATE_BYTES` 32 MB cap, 10 rotated files, 14-day retention (plan 02-03) |
| T-02-05-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs nothing; the capture pipeline is built from Pi's bundled example plus `node:fs`, and `tests/unit/pinning.test.ts:253` fails the build if a dependency is added |
</threat_model>

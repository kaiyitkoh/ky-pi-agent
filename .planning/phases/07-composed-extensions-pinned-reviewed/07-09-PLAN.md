<objective>
Write the lockfile and make it load-bearing: `.pi/settings.json` gains its `packages[]` array and
the `pi-subagents` configuration this phase depends on, and a new test diffs the array against a
committed expectation in both directions.

Purpose: criterion 1 says "`pi list` matches a committed lockfile with every version pinned
exactly". `pi list` reads installed packages **from settings** (Pi 0.84.1 `docs/packages.md:30`),
so `.pi/settings.json`'s own `packages[]` array IS the lockfile — no new file format is needed
(decision D-07-C). `.pi/settings.json` is currently `{}` and git-tracked, and
`tests/unit/pinning.test.ts`'s existing assertion — "every third-party entry carries a ref" —
currently passes vacuously. This plan is what makes it exercise real data for the first time.

The named trap: "a lockfile that nothing compares against". A committed list no test diffs is
decoration. The comparison must fail the build on drift AND — like Phase 6's workflow-budget
registry — fail when an installed package is **absent** from the lockfile, not only when a listed
one mismatches.

Two configuration facts this plan also settles, because nothing else in the phase can:
project-scoped agents under `.pi/agents/` are loaded **only** when `pi-subagents`' `agentScope`
is `"project"` or `"both"` (the default is user-level only), so plan 07-04's `planner.md` is
inert without it; and the worktree setup hook plan 07-02 authored is opt-in and disabled unless
configured (`pi-subagents src/runs/shared/worktree.ts:283`).

Output: `.pi/settings.json`, `tests/unit/extension-pins.test.ts`.
</objective>

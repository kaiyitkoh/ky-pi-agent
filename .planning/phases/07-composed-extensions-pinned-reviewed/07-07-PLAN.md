zero, and Phase 10 can gate vendored code this repo owns just as easily as third-party code it
does not.

<verified_composition_conflict>
Measured during planning by reading both bundled examples in full:

- `examples/extensions/plan-mode/index.ts:141` registers `/plan`, and **`:146` registers
  `/todos`** ("Show current plan todo list") over plan-extracted steps held in a local
  `todoItems` array.
- `examples/extensions/todo.ts:284` **also registers `/todos`**, over a model-maintained list
  backed by its `todo` tool (`todo.ts:136-137`).

Both are vendored by this phase (plan 07-08 vendors `todo.ts`). Two extensions registering the
same command name is a runtime collision that would be discovered by a user, not by a test.

**Resolution, settled here in one line (Standing Rule 8):** the general `/todos` name stays with
`todo.ts` — that is the capability EXT-05 names ("todo tracking") — and plan-mode's
plan-progress listing is renamed `/plan-todos`. It is a one-identifier edit to a vendored file,
recorded in the vendoring header and in `docs/EXTENSIONS.md`, and it preserves both capabilities
rather than dropping one.
</verified_composition_conflict>

<objective>
Ship the first `.pi/agents/*.md` subagent definition and the test that makes its most important
property mechanically true: it carries no `model:` key.

Purpose: EXT-01 wants per-agent model, system prompt, tool restriction and thinking level. Three
of those four live in the agent file. The fourth must NOT. Verified at source in
`pi-subagents@0.49.0 src/agents/agents.ts:1155`:

    if (override.model !== undefined && !agentHasFrontmatterField(agent, "model")) {

A settings-level `agentOverrides` entry **cannot beat** frontmatter — it only fills gaps.
`applySubagentDefaultModel` (`agents.ts:958`) bails identically on `if (agent.model !== undefined)
return agent;`, and the shipped `docs/models.md:12` precedence chain agrees. So a `model:` key in
any agent file this repo ships makes Phase 5's `.pi/extensions/routing/agent-overrides.ts`
**inert for that agent**. Omitting it is not hygiene; it is the mechanism. Pi's own bundled
samples (`examples/extensions/subagent/agents/{scout,planner,reviewer,worker}.md`) all carry one,
so copying them verbatim is the specific failure this test exists to prevent.

`thinking` IS a real frontmatter key (`agents.ts:1644`), which is what makes EXT-01's
thinking-level requirement satisfiable in the agent file at all — the bundled example's
`agents.ts` parses only `name`/`description`/`tools`/`model` and has no `thinking` key anywhere.
That single fact is the honest justification for depending on `pi-subagents` rather than
vendoring the bundled subagent example, and it belongs in the plan record.

Output: `.pi/agents/planner.md`, `tests/unit/subagent-agents-config.test.ts`.
</objective>

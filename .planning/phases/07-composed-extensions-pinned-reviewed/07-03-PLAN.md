<verified_mechanism_finding>
Measured on this machine (git 2.54.0.windows.1) during planning, NOT inherited from a document:

- `git stash create -u` **accepts** the `-u` flag and exits 0, but the resulting commit has only
  two parents and its tree contains no untracked file. The flag is accepted and ignored. A
  checkpoint built on it would grep green and capture nothing — precisely the "assert the flag,
  not the effect" trap this repo has hit before.
- The mechanism that DOES work, measured end to end: set `GIT_INDEX_FILE` to a scratch index
  under `.git/`, run `git add -A` (which respects `.gitignore`), `git write-tree`, then
  `git commit-tree <tree> -p HEAD -m <label>`. The resulting commit's tree contains both the
  tracked modification and the untracked file. Restoring with `git restore --source=<commit>
  --worktree -- .` (or `git checkout <commit> -- .`) puts both back. `git checkout <commit> -- .`
  additionally STAGES the restored paths into the real index; `git restore --worktree` does not.
</verified_mechanism_finding>

<objective>
Build the two pieces of machinery EXT-02 needs before it can be proven: a git-worktree test
helper, and the repo-authored setup hook that makes a fresh worktree buildable.

Purpose: `git worktree add` copies no untracked files. `.env` and `node_modules` stay behind by
design, which is exactly why a fresh worktree cannot build. `pi-subagents@0.49.0` has zero
handling for `.env` anywhere in the package, and its one `node_modules` remedy
(`src/runs/shared/worktree.ts:243-253`) calls an unqualified `fs.symlinkSync`, which fails
`EPERM` on Windows without Developer Mode and silently swallows the error. The sanctioned
injection point is `runWorktreeSetupHook` (`worktree.ts:336`) — a script this repo authors,
invoked with `spawnSync(hookPath, [], { cwd: worktreePath, shell: false })`. This plan writes
that script and the helper the next plan's proof needs.

Output: `tests/helpers/worktree.ts`, `.pi/scripts/worktree-setup-hook.mjs`.
</objective>

The hook contract, from `pi-subagents@0.49.0 src/runs/shared/worktree.ts:87-101, 318-379`
(reproduce it; it is external, there is no in-repo analog):

  WorktreeSetupHookInput = {
    version: 1;
    repoRoot: string;
    worktreePath: string;
    agentCwd: string;
    branch: string;
    index: number;
    runId: string;
    baseCommit: string;
    agent?: string;
  }

The hook receives that object as JSON on stdin and must print
`{"syntheticPaths": ["relative/path", ...]}` as JSON on stdout. `syntheticPaths` entries must be
relative, non-empty, and must not already be tracked in git; pi-subagents removes them before
every diff/cleanup pass, so a hook-created junction or copied `.env` is correctly excluded from
the agent's own patch output.

    `pi-subagents`' `runWorktreeSetupHook`. It must:

    Read all of stdin, parse it as JSON, and validate it against the `WorktreeSetupHookInput`
    shape in this plan's `<interfaces>` block: reject a payload whose `version` is not `1`, or
    whose `repoRoot` / `worktreePath` are missing or not absolute. On any validation failure,
    print a JSON object with an empty `syntheticPaths` array and a diagnostic on stderr, and
    exit non-zero — never emit a half-provisioned success.

    Assert containment before writing anything: `path.resolve(worktreePath)` must not equal and
    must not be an ancestor of `path.resolve(repoRoot)`. Provisioning "into" the parent repo is
    the one catastrophic failure mode here and must be impossible, not merely unlikely.

    Provision `node_modules`: if `<repoRoot>/node_modules` exists and `<worktreePath>/node_modules`
    does not, create a link with `fs.symlinkSync(nodeModulesSrc, nodeModulesDst, "junction")`.
    The third argument is the load-bearing detail — the unqualified two-argument form is what
    fails `EPERM` on Windows without Developer Mode, and it is precisely what `pi-subagents`
    does. On POSIX the third argument is ignored and an ordinary symlink is created. Do not
    swallow the error the way `linkNodeModulesIfPresent` does: catch it, report it on stderr,
    and exit non-zero so a degraded worktree is visible rather than silent.

    Provision `.env`: if `<repoRoot>/.env` exists, COPY it (`fs.copyFileSync`) to
    `<worktreePath>/.env`. Copy, not link — a shared `.env` mutated by one worktree would be
    seen by all of them and by the parent.

    Emit exactly one line of JSON on stdout: `{"syntheticPaths":[...]}` listing the relative
    paths actually created (`node_modules` and/or `.env`), and nothing else — any stray stdout
    output breaks the contract. Diagnostics go to stderr.

    Add a header comment recording the accepted residual from Addendum A3: the junction points

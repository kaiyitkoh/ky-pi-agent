<objective>
Build GATE-06 (refute-or-promote before a BLOCKER can stop work) and QUAL-05 (symptomatic/workaround changes stop
the workflow pending explicit approval).

The anti-review-theatre protocol is two-sided: LLM reviewers silently approve when unsure, AND a reviewer told to
find gaps invents them. Refute-or-promote is the countermeasure to the second failure mode, and it applies to
**BLOCKERs ONLY** — one refutation pass each, before a BLOCKER can stop work. A WARNING or a NIT never enters the
pass; widening it would cost a nested call per nit and would defeat the cap that exists to stop padding.

The loop is BOUNDED: BLOCKER → fix → re-review, at most 2 iterations, with stall detection (an iteration that
produces a finding set identical to the previous one is a stall and terminates the loop with a distinct outcome,
not another iteration).

QUAL-05's stop is a PURE predicate over a validated review. Where the approval is *collected* is Phase 9's
ceremonial-workflow problem; this phase produces the stop signal and its record.

Purpose: a BLOCKER that stops work has survived a challenge; a symptom patch cannot ship silently.
Output: `verdict.ts` and its scripted-outcome proof.
</objective>

    `export function decideWorkflowStop(review: ReviewArtifact): WorkflowStop` — first-match-wins with a NUMBERED
    BINDING-ORDER docstring:
      (1) `classification === "symptomatic"` → stop, `needsApproval: true`, reason naming the classification and

    `export function detectStall(previous: readonly ReviewFinding[], current: readonly ReviewFinding[]): boolean` —
    true when the two sets are equal under a normalised comparison (`severity|location|concreteFailure`, order
    independent). Stall means the loop is not converging.

    `export const MAX_REVIEW_ITERATIONS = 2;` — a named constant with a `why`.

    IMPURE half (one function, clearly separated):

    `export async function runRefuteOrPromote(ctx, review: ReviewArtifact, contract): Promise<{ readonly promoted: readonly ReviewFinding[]; readonly withdrawn: readonly {finding: ReviewFinding; rationale: string}[] }>`
    — for EACH BLOCKER, and only BLOCKERs, run exactly ONE nested `runSingleShotRole({role:"reviewer", ...})` pass
    with a REFUTATION system prompt that: states the finding verbatim; instructs the model to attempt to REFUTE its
    own finding using the same context contract; and requires a structured answer via a small forced tool
    (`refute_finding`, with `outcome: StringEnum(["upheld","withdrawn"])` and `rationale: Type.String()`). A response
    with no tool call, or an `outcome` outside the enum, counts as UPHELD — failing safe: an unparseable refutation
    must never silently delete a BLOCKER. State that fail-safe direction in the docstring; it is the opposite of the
    usual fail-closed instinct and needs saying.
    Never run a second pass on the same finding; one refutation pass each is the requirement's own wording.
    Time the passes and call `addQualityCost({ms, tokens})`.

    `export async function runBoundedReviewLoop(ctx, opts)` — orchestrates: review → if BLOCKERs, refute-or-promote
    → if any promoted, return a stop for the caller to act on → on a re-review, compare with `detectStall` and
    terminate with a distinct `outcome: "stalled"` rather than iterating again; hard-stop at
    `MAX_REVIEW_ITERATIONS`. Return a discriminated result carrying `iterations`, the final review, the withdrawn
    list and the stop decision — never a boolean.

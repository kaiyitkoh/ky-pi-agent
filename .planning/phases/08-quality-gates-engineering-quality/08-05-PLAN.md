<objective>
Fix the intermittently-red `tests/integration/qoder-delegate.test.ts` (red roughly 1 run in 5) at its root cause.
A suite that is only usually green makes every "tests green" claim in this project unfalsifiable — which is the
exact property this phase exists to establish. This is also the phase's canonical worked example of QUAL-04's
taxonomy: the root-cause fix is implemented and the symptomatic and workaround alternatives are named and rejected
in writing.

**The diagnosis is CONFIRMED and is not to be re-investigated.** The failing assertion is `qoder-delegate.test.ts:545-549`,
`expect(elapsed).toBeLessThan(400)`. `const start = Date.now()` is taken at `:523` BEFORE `delegateTask`, so
`elapsed` contains three HTTP round trips and six synchronous JSONL appends before the 60 ms deadline even arms at
`client.ts:706-710`. Total slack is 340 ms. Under vitest's default `pool:"forks"` with 17 of 33 integration files
spawning real child processes, 340 ms of combined fetch + fsync + timer drift on Windows is routinely exceeded.
Secondary manifestation of the same cause: starvation >400 ms BEFORE `client.ts:706` puts both server writes in the
socket buffer, the client never sees a gap, and `rejects.toThrow` at `:524` fails instead.

**Explicitly unacceptable**, each a QUAL-04 "symptomatic" or "workaround" by this phase's own definition: a retry;
a wider bound; raising `testTimeout` (already 120 s — the flake is not a timeout); `it.skip`; or
`fileParallelism: false`, which hides the same race behind a global slowdown.

Purpose: make the suite's green mean something.
Output: an event-gated loopback helper and a timing-free WR-07 assertion.
</objective>

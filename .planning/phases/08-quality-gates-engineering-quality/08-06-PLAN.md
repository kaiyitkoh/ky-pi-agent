<objective>
Build GATE-01's deterministic gate stage: typecheck, lint, LSP diagnostics and the QUAL-01 anti-pattern rules run
and feed errors back BEFORE any model review, adding no model round trip and no measurable wall-clock.

Three states per leg, and the third is the one that matters: PASS (ran, clean), FAIL (ran, found things — these
feed back before any model review), UNAVAILABLE (did not run). **UNAVAILABLE IS NOT A PASS.** An absent LSP that
reports "clean" is Phase 4's headless-guard failure in a new costume. The probe must read observable runtime state
(the registered tool-name list), never `.pi/settings.json` `packages[]` — that file lists five packages that are
pinned and NOT INSTALLED, so reading it would report available for a gate that cannot run.

QUAL-02's "no measurable wall-clock" is two separate claims and the plan makes both measurable: a STRUCTURAL claim
(the module's import graph contains no model-calling path) and a MEASURED claim (the anti-pattern legs' wall clock
against a stated budget). Measure it; do not assert it.

QUAL-07's design-review pass is a PREDICATE here, not a call: `shouldRunDesignReview` returns true only on named
signals or explicit escalation. Phase 9 dials gate depth (QUAL-08); this phase builds the mechanism.

Purpose: the best reliability-per-token item in the harness, feeding three downstream consumers.
Output: a pure gate runner and its three-state test table.
</objective>

      `npx tsc --noEmit`. Non-zero exit → `fail` carrying the compiler's own lines. A runner that throws (binary

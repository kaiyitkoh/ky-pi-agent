<objective>
Build GATE-02: the reviewer's fixed context contract, assembled and delivered through the Phase 2 chokepoint.

The contract is FIXED and COMPLETE and is not a preference: **diff + FULL CONTENTS of every touched file +
test/typecheck output + SPEC requirements + files-touched union + the import graph**. A reviewer seeing only the
diff misses bugs of omission and cross-file breakage — that is the documented cause. The test/typecheck output is
PASSED FROM the deterministic stage, never re-run.

The anti-review-theatre protocol is two-sided by design and its structural half lives here: fresh context (never
the implementer's reasoning), adversarial framing with a NAMED SOFT-FAILURE LIST ("stopping at surface issues",
"treating tests-pass as correctness", "downgrading BLOCKER to WARNING to avoid seeming harsh"), findings scoped to
correctness and stated requirements with NITs capped. The mandatory verdict / checked-and-cleared / classification
enforcement is code and already lives in plan 08-03's validator — this plan wires the prompt and the payload, and
the prompt is NOT the mechanism.

Dispatch is `runSingleShotRole(ctx, { role: "reviewer", ... , tools: [submit_review] })`. The role already exists
in `ROLE_MAP` with `reasoningEffort: "high"` in every mode. Do not invent a parallel role system and do not add a
second escape hatch around the chokepoint.

Purpose: the reviewer actually sees what it needs to catch a bug of omission.
Output: `reviewer.ts`, `.pi/agents/reviewer.md`, and the capture proof.
</objective>

    `export interface ReviewerContractInput { readonly diff: string; readonly touchedFiles: readonly {path:string; contents:string}[]; readonly gateReport: string; readonly requirements: readonly {id:string; text:string}[]; readonly filesTouchedUnion: readonly string[]; readonly importGraph: readonly {from:string; to:readonly string[]}[]; }`

    `export function buildReviewerContext(input: ReviewerContractInput): string` — PURE. Renders the six elements
    as six clearly-labelled sections in a FIXED order, each with a heading naming the element, and passes the whole
    rendered string through `redactString` from `diagnostics/redact.ts` before returning. Never re-implement
    redaction; the diff and the full file contents are exactly where a `.env` or `*.tfstate` the model read earlier
    would surface. A missing element is an ERROR, not an empty section: throw naming which of the six is absent, so
    a caller cannot half-satisfy the contract silently.

    `export function buildImportGraph(sources: readonly {path:string; text:string}[]): {from:string; to:string[]}[]`
    — PURE, syntax-level: collect each source's `import ... from "<specifier>"` targets. Note in the docstring that
    this is the *declared* graph, not a resolved module graph, and that dynamic imports are out of scope.

    `export const REVIEWER_SYSTEM_PROMPT` — the adversarial framing. Must contain, as explicit text:
      - the named soft-failure list, verbatim in substance: stopping at surface issues; treating tests-pass as
        correctness; downgrading BLOCKER to WARNING to avoid seeming harsh; approving when unsure
      - the instruction that findings are scoped to correctness and the stated requirements, with NITs capped at
        `NIT_CAP`
      - the instruction that a per-requirement verdict is mandatory for EVERY listed requirement id, and that a
        non-empty "checked and cleared" section is mandatory
      - the counter-instruction against the OTHER failure mode: a reviewer told to find gaps invents them, so a
        genuinely clean area is reported as cleared, never padded into a finding
      - the statement that `submit_review` is the only accepted output and prose outside it is discarded
    The prompt is a delivery mechanism, not the enforcement — say so in a comment referencing the validator.

    `export async function runReview(ctx, input: { contract: ReviewerContractInput; requirementIds: readonly string[] }): Promise<ReviewValidation>`
    — the ONE impure function. Builds the context, calls
    `runSingleShotRole(ctx, { role: "reviewer", systemPrompt: REVIEWER_SYSTEM_PROMPT, messages: [...], tools: [{ name: SUBMIT_REVIEW_TOOL_NAME, description: SUBMIT_REVIEW_DESCRIPTION, parameters: submitReviewParameters }], need: {} })`,
    extracts the `submit_review` tool-call arguments from the returned `AssistantMessage`, and returns
    `validateReview(args, requirementIds)`. An assistant message with NO `submit_review` call returns
    `{ok:false, reason: ...}` naming that prose was returned instead of a structured review — the "LGTM" path must
    fail here too, not only inside the validator. Wall-clock and token accounting: time the call and pass
    `addQualityCost({ ms, tokens })` using the returned message's usage; state in a comment that this is the
    quality layer's share, per QUAL-09.

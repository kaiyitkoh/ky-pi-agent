    Create `.pi/extensions/quality/rules.ts`. It is PURE: it takes `{ path: string; text: string }[]` and returns
    findings. It never touches `ctx`, never reads a file itself, never spawns anything, and registers nothing.

    Exports:
    - `export interface QualityFinding { readonly ruleId: RuleId; readonly path: string; readonly line: number; readonly tier: "error" | "warning"; readonly message: string; }`
    - `export const RULE_IDS = ["magic-number", "literal-special-case", "copy-paste", "swallowed-exception", "shipped-todo", "n-plus-one"] as const;` and `export type RuleId = (typeof RULE_IDS)[number];`
    - one exported function per rule: `ruleMagicNumber`, `ruleLiteralSpecialCase`, `ruleCopyPaste`,
      `ruleSwallowedException`, `ruleShippedTodo`, `ruleNPlusOne`, each `(source: QualitySource) => QualityFinding[]`
    - `export function runAntiPatternRules(sources: readonly QualitySource[]): QualityFinding[]` — dispatches all
      six over every non-exempt source, sorted by `path` then `line` so output is deterministic.
    - `export const SCAN_EXEMPT_PREFIXES = ["tests/fixtures/"] as const;` — a file whose repo-relative path starts
      with one of these is skipped entirely, with the reason stated in a docstring: the seeded-defect corpus of plan
      08-10 is by construction made of the shapes these rules detect, and scanning it would make the corpus
      un-shippable (RESEARCH Known Threat Patterns, last row).
    - `export const SUPPRESSION_MARKER = "quality-allow:";` — a `// quality-allow:<rule-id> — <reason>` comment on
      the offending line or the line above suppresses exactly that rule id at that node, and ONLY when a reason
      follows the em dash. A bare marker with no reason does not suppress; assert that direction.

    Every rule parses with `ts.createSourceFile(source.path, source.text, ts.ScriptTarget.Latest, /*setParentNodes*/ true)`
    and walks with `ts.forEachChild`. Line numbers come from
    `source.getLineAndCharacterOfPosition(node.getStart(source)).line + 1`.

    Rule definitions and their honest scope, each stated in its own docstring:
    - `magic-number` (tier `error`): a `ts.NumericLiteral` in a non-declaration position — i.e. NOT the initialiser
      of a `const` declaration, NOT a property in an object literal assigned to a `const`, NOT an enum member, NOT
      an array index literal 0/1, NOT `-1`, and not in a value set `{0, 1, 2, 100, 1000}` documented as the
      deliberate allowlist. Fires on the same literal appearing 2+ times in one file, and on any literal used as a
      comparison operand against a call result.
    - `literal-special-case` (tier `warning` — only partially decidable): an `if`/`switch` whose test compares a
      PARAMETER identifier against a string or numeric literal, inside a function whose other branches are generic.
      Docstring must state plainly that this cannot distinguish a legitimate dispatch table from a hack, which is
      exactly why it is WARNING tier and can never fail a build on its own.
    - `copy-paste` (tier `error`): two `ts.Block` nodes in the same source whose normalised token-kind sequence is
      identical AND at least 12 statements-worth long (state the threshold as a named constant, not a bare number
      in the walk — dogfood the magic-number rule). Normalisation drops identifier names and literal values, so
      renamed copies still match.
    - `swallowed-exception` (tier `error`): a `ts.CatchClause` whose block is empty, or whose block's only
      statements are a bare `return`/`return undefined`, UNLESS the enclosing function or the catch has a
      doc/leading comment containing a NEVER-THROWS contract marker (define `NEVER_THROWS_MARKERS = ["NEVER THROWS", "never throws"]`).
      This is the false-positive that matters most: `evidence.ts` and `safety/audit.ts` both ship this shape on
      purpose and both document it.
    - `shipped-todo` (tier `error`): a `TODO`, `FIXME`, `XXX` or `HACK` token in a COMMENT trivia range obtained via
      `ts.getLeadingCommentRanges`/`getTrailingCommentRanges` — never a substring scan of the whole text, which
      would flag the word inside a string literal or inside this rule's own definition.
    - `n-plus-one` (tier `warning` — only partially decidable): an `await` expression, or a call whose callee name
      matches a caller-supplied set (`N_PLUS_ONE_CALLEES`, default `["query", "exec", "fetch", "findMany", "get"]`),
      appearing syntactically inside a `for`/`for-of`/`while`/`.map(`/`.forEach(` body. The docstring must name the
      known false positive: this repo's own worktree tests legitimately run one `pi.exec` per worktree because no
      bulk git API exists.

    Module docstring must carry, verbatim in spirit, `evidence.ts:34-39`'s BOUNDARY RULE (BOOT-10) paragraph
    (this module registers nothing and does not spell the tool-registration call, in code or prose), plus a
    WHAT THIS DOES NOT PROVE section: syntax-only means no type information, so no rule here can know what a value
    IS, only how it is written.

    Chokepoint hygiene: this file sits outside `.pi/extensions/diagnostics/`, so it may not contain the strings
    `modelRegistry.complete`, `.completeSimple`, `.streamSimple`, `.getProvider`, `getRegisteredNativeProvider`,
    `ModelRuntime`, or a `@earendil-works/pi-ai/api/...` deep import — not even inside a comment.

<decisions_taken_here>
- **The script's CLI surface is `--check-only`, `--assert-hardening`, `--check-version`, `--help`, plus a bare full run.** RESEARCH specifies a `--check-only` mode for CI ("actually executes rather than merely building") and separately requires an assertion that fails *before* the first install. One flag cannot be both: `--check-only` must exit 0 on a clean CI runner where the user-scope control has not been applied yet, while the ordering proof needs a mode that exits 1 in exactly that situation. Splitting them is the smallest change that satisfies both.

</decisions_taken_here>

Create `bin/bootstrap.sh`. Strict POSIX `sh` throughout: `#!/bin/sh`, `set -eu`, no arrays, no `local` in a way that breaks dash, no `[[`, no `${var^^}`, no `sort -V`, no `jq`, no PowerShell equivalent. macOS runners ship bash 3.2 and BSD userland; the only safe target is `sh`.

Define at the top: `PI_PKG="@earendil-works/pi-coding-agent"`, `PI_PINNED="0.84.1"` overridable via `KYPI_PI_PINNED`, `PI_AGENT_DIR="${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}"`, `PI_NPM_ROOT="$PI_AGENT_DIR/npm"`, and `REPO_ROOT` derived from the script's own location so the script works from any cwd.

Implement these functions:

`require_node` — fail if `node` is absent; otherwise run a `node -e` snippet that splits `process.versions.node` and exits 1 below 22.19.0, naming the found version and the requirement. Using node to compare node's own version avoids every shell version-comparison trap and node is a hard prerequisite by definition.

`probe_tools` — print a fixed-width table with one row per tool and an explicit `required` or `optional` label. Required: `sh`, `git`, `node`, `npm`. Optional: `bash`, `gh`, `aws`, `glab`. A missing required tool is FATAL; a missing optional tool prints `WARN ... (optional)` and never aborts. `glab` is known absent on this machine and on both CI runners, so it must be optional; GitLab work is Phase 4/9 and lives on the work laptop. The strings `glab` and `optional` must both appear in stdout on every run so the BOOT-03 assertion is not platform-dependent.

`check_pi_version_published` — run `npm view "${PI_PKG}@${PI_PINNED}" version --json`. Treat success as published. On failure, discriminate on the literal string `E404` in the captured output: E404 means unpublished and prints a FATAL block naming the pinned version, the current `latest` (best-effort via a second `npm view`, degrading to `unknown`), the fact that Earendil Works unpublishes old versions and everything below 0.74.0 is already gone, and a three-step numbered Fallback naming `KYPI_PI_PINNED` / the `PI_PINNED` line in this script, re-reading Pi's CHANGELOG for breaking extension-API changes, and re-running. Anything else is a registry-unreachable WARN-then-exit that must **not** contain the words "unpublished" or "yanked" — an offline user must never be told their pin was withdrawn.

`assert_ignore_scripts_for <label> <cwd-or-empty> <prefix-or-empty>` — run `npm config get ignore-scripts`, with cwd or `--prefix` per the arguments, and require the literal output `true`. On failure print `FATAL: ignore-scripts is not enabled for <label> (got: <value>)` followed by `Refusing to run pi install: npm lifecycle scripts would execute before review.` and exit 1. Assert the *effect* via `npm config get`, never the existence of the file — RESEARCH §1.3 proved a correctly-placed file can still be ineffective.

`harden_pi_npm_root` — `mkdir -p "$PI_NPM_ROOT"`, write `.npmrc` there containing `ignore-scripts=true` with a provenance comment if absent or lacking the line, then call `assert_ignore_scripts_for` against that prefix. Pi creates this directory itself (`ensureNpmProject`, `package-manager.ts:1975-1986`) and only ever creates files that are absent, so this file survives.

`install_pi` — no-op with a message when `npm ls -g --depth=0 --json` already shows the pinned version; otherwise run `npm install -g --ignore-scripts "${PI_PKG}@${PI_PINNED}"`, mirroring Pi's own self-update shape at `src/config.ts:170-177`. Skip entirely when `KYPI_SKIP_INSTALL` is set to `1`.

`merge_settings` — key-namespaced merge into `$PI_AGENT_DIR/settings.json` via `node -e` read/parse/merge/write, touching only the `kyPiAgent` key (fields: `bootstrapVersion`, `hardenedNpmRoot`, `piPinned`) and writing back with 2-space indentation. Never rewrite the whole file, never use `sed`/`awk` on JSON, never require `jq`. Creates the file as `{}` first if absent.

`write_env_template` — copy `.pi/templates/env.example` into `<REPO_ROOT>/.env.example`, replacing only the content between `# ky-pi-agent managed:start` and `# ky-pi-agent managed:end` when the target already exists, and appending the block when the markers are absent. Byte-identical on a second run.

Wire the modes. Bare invocation runs, in this exact order: `require_node`, `probe_tools`, `check_pi_version_published`, `assert_ignore_scripts_for repo-root`, `assert_ignore_scripts_for project-prefix <REPO_ROOT>/.pi/npm`, `harden_pi_npm_root`, **then** `install_pi`, `merge_settings`, `write_env_template`, and a final summary. The three hardening steps precede `install_pi` and that ordering is the literal BOOT-01 requirement — add a comment saying so.

`--check-only` runs `require_node`, `probe_tools`, `check_pi_version_published`, and the two repo-side hardening assertions, mutates nothing, and treats a missing `$PI_NPM_ROOT/.npmrc` as a WARN naming the remedy (`run bin/bootstrap.sh with no arguments to apply`) rather than a FATAL — this mode must exit 0 on a clean CI runner. It must produce byte-identical stdout on consecutive runs, so it may not print timestamps, durations, absolute temp paths, or cost figures.

`--assert-hardening` runs only the three `assert_ignore_scripts_for` checks including `$PI_NPM_ROOT`, mutates nothing, and exits 1 with `ignore-scripts` on stderr if any scope is ineffective. This is the ordering test seam and the runbook re-check.

`--check-version` runs only `check_pi_version_published`.

`--help` prints the mode list and the two env seams, and exits 0.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → global npm prefix | `npm install -g` fetches and, without `--ignore-scripts`, executes arbitrary code as the user |
| bootstrap script → user home directory | The script writes into `~/.pi/agent`, which holds credentials, trust decisions and full session transcripts |
| npm registry availability → user's mental model | A misclassified failure tells the user their pinned host was withdrawn when the network merely blinked |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Elevation of Privilege | `pi install` executing lifecycle scripts before any review | mitigate | Three `assert_ignore_scripts_for` calls plus `harden_pi_npm_root` all execute before `install_pi` in the full-run path; each asserts npm's reported effective config, not file presence |
| T-01-15 | Elevation of Privilege | `npm install -g` of Pi itself running install scripts | mitigate | `--ignore-scripts` on the global install, mirroring Pi's own self-update at `src/config.ts:170-177`; free, since Pi ships no postinstall |
| T-01-06 | Tampering | Stale global Pi silently changing extension-API behaviour | mitigate | `install_pi` compares `npm ls -g --depth=0 --json` against the pin and re-installs on mismatch; `--check-only` re-reports it every run |
| T-01-16 | Spoofing | A registry outage misreported as an unpublished version | mitigate | Discrimination on the literal `E404` token, asserted by version-gate case 3, which also asserts the absence of yank wording |
| T-01-17 | Tampering | A non-idempotent edit corrupting `~/.pi/agent/settings.json` | mitigate | Key-namespaced `node -e` read/parse/merge/write on the `kyPiAgent` key only; never `sed`/`awk` on JSON; never a whole-file rewrite. `pi remove <source>` is documented as the undo |

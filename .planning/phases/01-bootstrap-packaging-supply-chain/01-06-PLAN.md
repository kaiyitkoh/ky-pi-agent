Assert exit code 1 and that stderr contains the literal `ignore-scripts`. This is the negative half of the ordering requirement: without the control, the script refuses.

Case 2 — **assert-hardening passes once the control is written.** Write `ignore-scripts=true` into `<tempDir>/npm/.npmrc`, re-run the same command, assert exit 0. Without this case, case 1 could pass because the script always fails.

Case 3 — **the recorded invocation order.** Use `withStubBin` to place stubs for `npm` and `pi` on `PATH`, each appending its own name and full argv to a shared log file. The `npm` stub must reproduce the real responses the script depends on: `npm config get ignore-scripts` prints `true`, `npm view ... version --json` prints a valid version string, `npm ls -g ...` prints an empty tree, and anything else exits 0 silently. Run the script with no arguments and `PI_CODING_AGENT_DIR` on a temp directory. Then parse the log and assert that the index of the **last** `npm config get ignore-scripts` line is strictly less than the index of the **first** line matching `npm install` or `pi install`. Assert the log contains at least one `npm config get ignore-scripts` entry and at least one install entry, so the ordering assertion cannot pass vacuously on an empty log.

Add a docstring recording why the log is the proof rather than source-order inspection: `event.input` mutation and conditional branches mean a later hook or a refactor can reorder execution without reordering the file, and the requirement is about execution order.

## Summary

Pi 1.1.0 loads exactly one context file per directory, first match of `AGENTS.override.md, AGENTS.md, AGENTS.MD, CLAUDE.md, CLAUDE.MD`, from the global agent dir and then every ancestor of cwd, and does no `@` expansion. So a new root `AGENTS.md` makes Pi in this repo skip the 49 KB `CLAUDE.md` entirely, and `CLAUDE.md` starting with `@AGENTS.md` makes Claude Code read the same rules (Claude Code docs confirm `@path` imports expand at launch, max four hops, and that keeping `@AGENTS.md` never causes a double read). GSD's CLAUDE.md generator only rewrites text inside its own `<!-- GSD:...-start/-end -->` markers and appends missing sections, so a first line `@AGENTS.md` outside any marker survives.

For delivery to other projects, use the harness extension, not a bootstrap-written global file. In 1.1.0 `before_agent_start` receives a mutable `systemPromptOptions.sections` map; assigning a named section (`code_comments`) adds a static `<code_comments>` block at the end of the prompt without replacing the prompt (returning `systemPrompt` would set `forceSystemPrompt`, which is opaque and replaces everything). This works for `pi install` users in every project, needs no manual step, is user-scope (not gated by project trust), and has a precedent in this repo (`background-tasks/src/core/shell-policy.ts:130-162`). The extension should skip injection when a loaded context file already contains the rule heading (this repo's own `AGENTS.md`), avoiding a duplicate.

The cleanup is large and the real risk is bookkeeping, not logic. Measured over the 52 tracked authored files (TypeScript AST comment ranges): 12,230 comment-only lines vs 8,525 code lines = 58.9%, and 1,092 ID-shaped tokens in comments. Reaching ≤35% means deleting about 7,640 comment lines (62% of them). Because `tests/unit/workflow-budgets.test.ts` asserts every file and directory budget equals the measured raw line count rounded up to the next ten (exact `toBe`, lines 848-857 and 1038-1046), every cleanup plan MUST lower the matching budget numbers in the same commit. Also, `quality/rules.ts` excuses a swallowed `catch` only when a `NEVER THROWS` comment is nearby, so those marker comments must survive (67-finding budget at `quality-rules.test.ts:339`). Zero-behaviour-change is cheaply provable: `ts.transpileModule(..., {removeComments: true})` output is identical before and after (validated this session across all 73 tracked files with every comment blanked: 0 diffs, with a negative control).

**Primary recommendation:** Ship the rule text as one TS constant used by both the harness injection and a parity test against `AGENTS.md`; land the ID check first with an explicit `PENDING_CLEANUP` ratchet list so the suite stays green per plan; clean one subsystem per plan, lowering the workflow-budget numbers each time and verifying with a transpile-equality test gated on a base ref.

### Comment extraction (robust, validated)

```typescript
// tests/helpers/comment-scan.ts (sketch; validated in scratch against all 73 tracked files)
import ts from "typescript";
export interface CommentRange { pos: number; end: number; text: string }
export function extractComments(text: string): CommentRange[] {
  const sf = ts.createSourceFile("x.ts", text, ts.ScriptTarget.Latest, false, ts.ScriptKind.TS);
  const seen = new Map<number, ts.CommentRange>();
  const add = (r?: ts.CommentRange[]) => r?.forEach((c) => seen.set(c.pos, c));
  const walk = (n: ts.Node): void => {
    const kids = n.getChildren(sf);
    if (kids.length === 0) {               // leaf token incl. EndOfFileToken
      add(ts.getLeadingCommentRanges(text, n.getFullStart()));
      add(ts.getTrailingCommentRanges(text, n.getEnd()));
    } else kids.forEach(walk);
  };
  walk(sf);
  return [...seen.values()].sort((a, b) => a.pos - b.pos)
    .map((c) => ({ pos: c.pos, end: c.end, text: text.slice(c.pos, c.end) }));
}
```
Why this over the scanner: comments are trivia attached to leaf tokens, so strings, template literals and regex literals can never be mistaken for comments. Cost: about 0.7 s for all 73 files (measured), fine in vitest. `typescript` is imported at runtime by tests already (`docs-policy.test.ts:48` imports `quality/rules.ts` which imports `ts`).

Line classification (reproduces CONTEXT's 55% baseline: 13,175 comment / 10,731 code over the 59 non-background-tasks files = 55.1%): build a char mask of comment ranges; per non-blank line, `comment-only` if every non-whitespace char is masked, else `code` (lines with a trailing comment count as code). `ratio = commentOnly / (commentOnly + code)`. Blank lines excluded. Blank ` *` lines inside block comments count as comment-only (all non-whitespace chars are masked, and a lone ` *` is non-whitespace).

### ID token regex

Measured on authored comments (52 files), the prefixes seen are: `T-` (threat ids, 135), `Phase N` (114), `WR-` (103), `CR-` (94), `QUAL-` 69, `ROUTE-` 66, `SAFE-` 63, `DIAG-` 51, `BOOT-` 46, `plan N-M` 66, `GATE-` 39, `RB-` 26, `FLOW-` 25, `iteration N` 19, `PROV-` 17, `WR2-`/`CR3C`-style 28, `IN-` 7, `EXT-` 5, `EV-` 5, `CTX-`, `UPG-`, plus doc-name forms `NN-RESEARCH`, `NN-CONTEXT`, `NN-REVIEW`, `NN-NN-SUMMARY`.

Recommended (generic uppercase-prefix form with a small non-ID exception set, so new prefixes are caught without editing the regex):
```typescript
export const ID_PATTERN = new RegExp(
  String.raw`\b(?:` +
  String.raw`[A-Z][A-Z0-9]{0,5}-\d{1,3}(?:\.\d+)?(?:-\d{1,3})?` +                 // WR-15, T-04-01, RB-01-03, WR2-04, D-02
  String.raw`|(?:[Pp]hase|[Pp]lan|[Ii]teration)\s+\d+(?:\.\d+)?(?:-\d+)?` +         // Phase 7, plan 08-11, iteration 3
  String.raw`|\d{2}(?:\.\d)?-(?:\d{2}-)?(?:RESEARCH|REVIEW|CONTEXT|PLAN|SUMMARY|VERIFICATION|UAT)` + // 08-RESEARCH, 07-07-SUMMARY
  String.raw`)\b`, "g");
export const NON_ID_TOKENS = /^(?:UTF-8|UTF-16|SHA-1|SHA-256|SHA-512|AES-256|ISO-8601|HTTP-2|GPT-\d|TLS-1)$/; // extend only with evidence
```
Deliberately NOT matched: bare `NN-NN` (e.g. `50-56`, `65-71`): these are legitimate file:line range cites in comments (measured: 405 numeric-only hits, the top non-doc ones are line ranges). 4-digit suffixes (`CVE-2021`, `ES-2022`) are not matched by `\d{1,3}\b`. Measured against authored comments this matches 1,092 tokens; CONTEXT's 808 came from a narrower prefix list, so quote 1,092 when sizing. No tech-token false positives were found in the authored set (exception list is precautionary; the self-test fixture must include `UTF-8` and `50-56` as must-not-match and `WR-15`, `Phase 7`, `plan 08-11`, `08-RESEARCH` as must-match).

Vendored-exempt set (explicit constant, not marker discovery): `.pi/extensions/background-tasks/**`, `loop-police/**`, `plan-mode/**`, `todo.ts`, `questionnaire.ts` (matches `MUST_BE_VENDORED` in `vendor-license-audit.test.ts:82-130` minus checkpoint). **`checkpoint/` is registered as vendored but is "RE-AUTHORED, NOT COPIED — no line of the upstream file survives" (`checkpoint/PROVENANCE.md`), 64% comments, 38 IDs: treat it as authored, and it is in CONTEXT's "first" list.** Add a sanity assertion that every exempt path is tracked (catches renames).

### Anti-Patterns to Avoid
- **Regex comment stripping in the new check:** mangles `//` in strings and regexes; use the AST ranges.
- **Marker discovery for exemption:** `VENDORED` markers also appear in `checkpoint/*`, which must be cleaned.
- **Editing code while cleaning:** any non-comment change fails the equivalence verifier; even "while I'm here" renames.
- **Deleting comments adjacent to `NEVER THROWS`, `quality-allow:`, or the vendoring header lines** (see Pitfalls).
- **Running vitest in parallel across plans** (D-06): CPU pegged to 99% historically.

## Common Pitfalls

### Pitfall 1: Budget ratchet failures after every shrink
**What goes wrong:** `workflow-budgets` fails with "budget must be N" for each cleaned file/dir.
**Why:** Exact-match rule (#1, #2), not a ceiling.
**How to avoid:** Edit both the file and directory numbers in the same commit; use the failure message's `N`.
**Warning signs:** red `workflow-budgets` only for the subsystem just edited.

### Pitfall 2: Silently adding error-tier quality findings
**What goes wrong:** Removing a `NEVER THROWS` comment turns a deliberate `catch { return undefined; }` into an error finding; total exceeds 67.
**How to avoid:** Keep the phrase on the nearest leading comment of the catch or its enclosing function (the rule climbs to the function-like node, `rules.ts:578-589`); the equivalence test counts markers.

### Pitfall 3: Dropping the vendoring header from `checkpoint/index.ts`
**What goes wrong:** vendor-license-audit Direction 4 and tool-count-baseline discovery shrink or desync (#6).
**How to avoid:** Keep one marker line; PROVENANCE.md carries the real record.

### Pitfall 4: ID check green by accident
**What goes wrong:** A scanner bug finds zero comments and passes.
**How to avoid:** Non-vacuity assertions and an inline offending fixture (house style, e.g. `chokepoint-lint.test.ts`).

### Pitfall 5: `@AGENTS.md` ignored by Pi
**What goes wrong:** Someone expects Pi to expand it. It does not; AGENTS.md must be self-sufficient and CLAUDE.md is invisible to Pi in this repo.

### Pitfall 6: Duplicate rule text in this repo's Pi prompt
**What goes wrong:** AGENTS.md block plus the injected section.
**How to avoid:** Skip injection when a context file already contains the heading; test both cases.

### Pitfall 7: Hook ordering with `forceSystemPrompt`
**What goes wrong:** If an earlier extension returned `systemPrompt`, `sections` edits are ignored for that run.
**How to avoid:** Mirror `shell-policy.ts` (append to the forced string once).

### Pitfall 8: Cleaning removes the only documentation of a Pi fact
**What goes wrong:** Facts like `dist/core/extensions/runner.js:280-291` (first-registration-wins) live only in comments; safety-entry test messages reference them.
**How to avoid:** Keep as one-line cite. If something is large, move to `docs/` rather than deleting.

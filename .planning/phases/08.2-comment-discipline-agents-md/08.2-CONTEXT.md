<decisions>
## Implementation Decisions (user-locked 2026-10-12: "rule + ID check + cleanup")

- **D-01** Root `AGENTS.md` = universal cross-agent instruction file (Codex, Pi, others read it). `CLAUDE.md` first line `@AGENTS.md` (Claude Code expands imports; Pi does NOT expand `@` and loads the FIRST of `AGENTS.override.md, AGENTS.md, AGENTS.MD, CLAUDE.md, CLAUDE.MD` per directory — so Pi in this repo will load AGENTS.md instead of the 49 KB CLAUDE.md, which also removes ~97% of the current 12.7k-token Pi prompt). Re-verify loader order in Pi 1.1.0 `dist/core/resource-loader.js`. Keep AGENTS.md short — every line is per-turn cost; Phase 10 will budget it.
- **D-02** The comment rules must reach the user's OTHER projects when Pi runs there (primary intent). Choose mechanism from 1.1.0 source: (a) harness extension appends a static block via `before_agent_start` (works for `pi install` users; static text keeps the cache prefix stable), or (b) bootstrap writes/merges `~/.pi/agent/AGENTS.md` (global file loaded first; must not clobber user content). Prefer the one that needs no manual step and is cache-safe; justify.
- **D-03** Rule text (starting point, ≤15 lines, refine):
  ```
  ## Code comments
  - Default to no comment. Names and types say WHAT; comment only non-obvious WHY: a constraint, invariant, workaround, or surprising choice.
  - One or two lines. Longer explanation belongs in docs/ or the commit message.
  - Never narrate code ("loop over items", "set default") or restate a signature.
  - No history: no plan/phase/requirement/review IDs, no "previously", "fixed", "corrected by". Git holds that.
  - No caller/task references ("used by X", "added for Y flow"); they go stale.
  - Cite an external fact as one line with file:line or URL, not a quoted analysis.
  - JSDoc only on exported API: one sentence plus non-obvious params.
  - When editing code, update or delete its comments; a wrong comment is worse than none.
  - Vendored files are exempt.
  ```
- **D-04** Vitest check: fail on ID-shaped tokens in comments of authored `.pi/extensions/**/*.ts` (pattern like `\b(RB|CR|WR|IN|D|ROUTE|QUAL|DIAG|BOOT|SAFE|GATE|EXT|FLOW|CTX|UPG|CMT)-\d+`; vendored excluded). Comment ratio: REPORTED (or loose per-file ceiling), not a hard fail. No ESLint.
  - Careful: some tests/docs-policy checks may assert ID strings appear in code or docs (e.g. `docs-policy.test.ts`, RB-ID traceability). Planner must grep tests for ID/comment coupling and move traceability to docs/.planning, not code comments.
- **D-05** Cleanup pass per subsystem (diagnostics, routing, checkpoint first, then the rest): strip IDs/history/narration, shrink banners to 1-3 lines, KEEP safety invariants and Pi-source facts as one-line file:line cites. Comments only — zero behaviour change. Target overall ratio ≤35% (currently 55%: 13,272 comment vs 10,762 code lines across 60 files; 808 ID tokens).
- **D-06** CPU budget: `--maxWorkers=2`, targeted tests per plan, `tsc --noEmit` per plan, full suite once at verification. Plans touching disjoint subsystems still run sequentially (no concurrent test runs).

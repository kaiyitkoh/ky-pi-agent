## Info

### IN-01: The version anchor rejects a version that ends a sentence and accepts any word followed by a semver

**File:** `tests/helpers/comment-scan.ts`, the `VERSION_ANCHOR` constant (`/[\w-][ @]v?\d+\.\d+\.\d+(?![.\d])/`)

**Issue:** These results were confirmed with node:

| Text before the citation | Result | Effect |
|---|---|---|
| `"read at pi 1.1.0. See runner.js:3"` | Not an anchor | False positive. The `(?![.\d])` lookahead that rejects IPs also rejects a full stop. |
| `"node 24.16.0 "` | Anchor | Any word followed by a semver counts. |
| `"took 1.2.3 "` | Anchor | Same. |

A version from a *different* package within 60 characters also anchors a citation. The false positive fails loudly. The loose matches are a residual bypass, but a narrow one.

**Fix:** Use `(?!\.?\d)` so that a sentence-final full stop is allowed. Optionally restrict the anchor word to `pi|pi-ai|[\w@/-]+@`.

### IN-02: Widening to `.md`/`.json` and bare basenames sends common external names to the in-repo gate

**File:** `tests/helpers/comment-scan.ts`, `LINE_CITATION` and `isRepoCitation`

**Issue:** An external citation can share a basename with a tracked file. Examples are `pi-subagents@0.76.1 README.md:40`, `package.json:12` and a bare `index.ts:N`, because the repo tracks `README.md`, `package.json` and 15 `index.ts` files. These are classified as in-repo and flagged as stale line citations, even when they carry a version.
- None occur today.
- The failure is loud, so the gate does not silently pass them.
- The in-repo branch also skips the version check, but the in-repo gate catches the same token, so no hole results.

**Fix:** Treat a citation as external when a version anchor immediately precedes it. Alternatively, require that `findRepoLineCitations` sees no anchor within the window.

### IN-03: The comment-only verifier mixes working-tree contents with an index-based file list

**File:** `tests/unit/comment-only-diff.test.ts`, the `pairs`/`added` construction (`authoredFiles()` → `trackedFiles`, then `readFileSync`)

**Issue:**
- The *contents* compared come from the working tree, but the *file set* comes from `git ls-files`.
- An untracked new extension file is invisible to the new "adds no authored file" gate, even though Pi auto-discovers it at runtime. The untracked `.pi/extensions/execute/progress.ts` in this worktree is an example.
- The verdict therefore describes neither the commit nor the runtime exactly.

**Fix:** Either compare `REF` with `HEAD` throughout (`git show HEAD:<p>` and `git ls-tree HEAD`), or add `git ls-files --others --exclude-standard -- .pi` to `added`.

## Summary

The comment-only cleanup changed no behaviour. All 51 changed `.pi/extensions/**/*.ts` files outside `harness/` have identical code-token sequences and identical comment-stripped emit at 25518c6 and HEAD. The harness `before_agent_start` injection is correct against Pi 1.1.0's `emitBeforeAgentStart` and `buildSystemPromptSections`, and `tsc --noEmit` is clean.

The defects are in three areas:
- **Stale comments.** The cleanup rewrote files that other comments cite by line number, so those citations now point at the wrong code. It also removed the version anchors from upstream Pi citations.
- **One misleading safety comment.** The `paths.ts` invariant comment now contradicts how `policy.ts` actually calls it.
- **Soundness gaps in the new gates.** The comment-only verifier is skipped by default, cannot detect deletions and erases type-level changes. The ID gate does not scan `.pi/lib`. The dedupe check is a raw substring match, and the forced-prompt branch has no test.

**Files:**
- `.pi/extensions/routing/index.ts:304` cites `safety/index.ts:832-838`. That file is now 525 lines long; the cited lines no longer exist.
- `.pi/extensions/quality/index.ts:151` cites `safety/index.ts:32-46`. Those lines are now the `APPROVE_CHOICE` and `DENY_CHOICE` constants, not the registration-order rationale.
- `.pi/extensions/execute/handoff.ts:156` cites `diagnostics/budget.ts:223-225`. Those lines are now `toolSchemaChars` and `recomputedSkills`, not `estimateTokensFromChars`.
- `.pi/extensions/routing/modes.ts:36` cites `diagnostics/index.ts:192-224`. Those lines are now the `inFlight`/active-tool code, not the globalThis counter rationale.
- `.pi/extensions/workflows/index.ts:69` cites `safety/git.ts:171`. That line is now a closing `});`.

**Issue:** The cleanup shrank every target file by 40–60%, and none of the references into those files were updated. At base, `estimateTokensFromChars` was at `budget.ts:225` and the globalThis-counter docstring was at `diagnostics/index.ts:192`. AGENTS.md's own rule says "a wrong comment is worse than none", and the phase introduced these errors.

For example, use `safety/git.ts#currentSha` and `diagnostics/budget.ts#estimateTokensFromChars`. Optionally add a check to `comment-discipline.test.ts` that rejects `<repo-path>.ts:<n>` citations in comments.

### WR-02: Version anchors removed from upstream Pi citations; the bare line numbers are now wrong

**Files:** across `.pi/extensions` (135 `*.js|ts|d.ts:N` citations remain). Examples: `safety/index.ts:4` (`runner.js:280-291`), `safety/index.ts:81` (`runner.js:861-870`), `safety/index.ts:143` (`agent-loop.js:444-449`).

**Issue:** The diff removes 91 occurrences of `0.84.1` and 15 of `1.1.0` and adds back only 3. Citations that said "pi 0.84.1 X.js:N" now read as bare `X.js:N`. Checked against the installed 1.1.0:
- `runner.js:280-291` is provider/virtual-model registration; first-registration-wins is at `:410`.
- `runner.js:861-870` is the tail of `emitInput`.
- `agent-loop.js:444-449` is the parallel-execution closure, not "a throw becomes isError".

The harness header also lost "0.84.1" from `openai-completions.ts:1337-1370`. A reader following these citations lands on unrelated code. This is the "verify at source" discipline the project depends on.

**Fix:** Restore a version qualifier on every external citation (`pi 0.84.1 runner.js:861-870`), or re-verify against 1.1.0 and cite that version. Add a test that rejects a `dist/…js:N` citation without a `@x.y.z` or `pi x.y.z` qualifier.

### WR-03: `safety/paths.ts` invariant comment contradicts the bash caller in `policy.ts`

**File:** `.pi/extensions/safety/paths.ts:9-11` vs `.pi/extensions/safety/policy.ts:158-160`

**Issue:** The condensed header states as an invariant: "Normalise on `Word.text`, never `.value` … stripping one pair of quotes from `.text` yields the same path for all three quoting forms." But `policy.ts:160` passes `{ text: arg, value: arg }`, where `arg` is already `Word.value`-resolved. Its own comment on line 158 says the opposite: "Args are Word.value-resolved, so an unquoted Windows path through bash may mangle." The known gap is EV-27 (unquoted `C:\…\.aws\credentials` through bash is not blocked). Someone reading only `paths.ts` would conclude it is closed. A false safety claim in the guard is the most harmful kind of wrong comment.

**Fix:** In `paths.ts`, state that the module normalises whatever arrives in `.text`, and that the bash caller currently supplies `Word.value` (EV-27, docs/SAFETY.md). Or thread `Word.text` through `CanonicalInvocation` as SAFETY.md proposes.

### WR-04: The comment-only verifier is weaker than claimed, and it fails against the phase's own base

**File:** `tests/unit/comment-only-diff.test.ts:26,32-44,53-60`; `tests/helpers/comment-scan.ts:105-110`

**Issue:**
1. `describe.skipIf(REF === "")` means the gate never runs in a default `vitest run` or in CI. It only proves anything when someone remembers to set the env var.
2. The "keeps every file present at the ref" check is vacuous. It iterates `authoredFiles()`, which comes from current `git ls-files`, so a file deleted since the ref is never visited. `deleted` can only fill for a file that is tracked but missing from disk.
3. `transpileModule` erases types, so edits to type annotations, interfaces, `as const` or `readonly` pass as "comment-only". The plan's "every non-comment byte stays identical" is not what this checks.
4. There is no allowance for files whose behaviour changed deliberately. Run against the phase base, `COMMENT_BASE_REF=25518c6` fails on `harness/index.ts` (confirmed), so the whole phase cannot be verified in one run. The summaries used per-plan refs instead.

**Fix:**
- Compute the file set as the union of `git ls-tree -r --name-only REF` and the current tracked files, and fail on paths that exist only at the ref.
- Compare scanner tokens (`ts.createScanner(..., skipTrivia=true)`, kind + text), not transpiled output.
- Accept an explicit `COMMENT_DIFF_EXEMPT` list for deliberately changed files.
- Optionally run the gate in CI against `git merge-base HEAD origin/main`.

### WR-05: Dedupe is a raw substring match, so it has false positives and false negatives

**File:** `.pi/extensions/harness/index.ts:25` (and `:27` for the forced prompt)

**Issue:** `f.content.includes("## Code comments")` also matches:
- `### Code comments` (contains the substring);
- a fenced code sample or quoted text mentioning the heading;
- an unrelated `## Code comments` section with opposite rules in any ancestor or global `AGENTS.md`.

In each of these cases the harness rules are silently dropped. In the other direction, `## Code Comments` (capital C) or `##  Code comments` does not match, and the rules are delivered twice. The same substring logic guards the forced-prompt append.

**Fix:** Match a heading line: `/^##[ \t]+code comments[ \t]*$/im.test(f.content)`. Document that any project section with this heading replaces the harness rules.

### WR-06: The forced-prompt branch has no test and diverges from the structured path

**File:** `.pi/extensions/harness/index.ts:26-33`; `tests/unit/comment-rules-delivery.test.ts:131-158`

**Issue:** No test drives a session in which an earlier `before_agent_start` handler returns `systemPrompt`. The append, the no-double-append check and handler ordering are all unverified; the only related test (`:155-157`) greps the source for `systemPrompt:`.

The branch also returns before setting `sections.code_comments`. Pi still diffs and persists the structured sections even when a forced prompt is projected (`agent-session.js:1303-1309`). So a transcript recorded during forced runs lacks the section, and the first unforced turn emits a mid-conversation section patch. The bundled `background-tasks/src/core/shell-policy.ts:156-160` does both (sets the section and patches the forced text).

An empty forced prompt (`""`) also gets the rules appended, which overrides a deliberately empty system prompt.

**Fix:** Always set `o.sections[COMMENT_RULES_SECTION]`, and additionally patch `forceSystemPrompt` when it is a non-empty string without the heading. Add a faux-session test that loads an extra extension returning `{ systemPrompt: "X" }` and asserts that the outgoing prompt contains the rules exactly once.

### WR-07: The ID gate does not scan `.pi/lib`, and the regex misses common ID shapes

**File:** `tests/helpers/comment-scan.ts:60-67,95-99`

**Issue:** `authoredFiles()` scans only `.pi/extensions`. `.pi/lib/{jsonl,win-quote,work-artifacts}.ts` is authored runtime code imported by `safety/audit.ts` and others, and still has **29** ID hits in comments.

The pattern also misses:
- letter-suffix decision IDs (`D-D`);
- IDs with 4 or more digits (`ADR-0001`);
- lowercase IDs (`wr-01`);
- issue numbers (`#6998`);
- bare plan IDs (`08.2-13`).

A wider ad-hoc scan of HEAD found no such leftovers in `.pi/extensions` today, so this is a ratchet gap, not a current violation.

**Fix:** Include `.pi/lib` in `authoredFiles()`, or justify the exclusion in AGENTS.md. Extend the pattern with `\bD-[A-Z]\b`, `\b[A-Z]{2,6}-\d{4}\b` (with an allowlist for CVE-style tokens) and `#\d{3,}`.

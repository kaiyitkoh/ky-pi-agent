<objective>
Classify the infrastructure verbs into three buckets — allow outright, require confirmation,
and sensitive-read block — so that `terraform apply|destroy|import`, mutating `aws` calls and
`kubectl delete` gate while the commands a session uses to orient itself do not.

Purpose: this is the requirement most likely to be shipped backwards. A guard that prompts on
`aws sts get-caller-identity` — the first call a session makes — trains the user to approve
reflexively, which Pitfall 4 identifies as a worse posture than no gate at all. And in the
user's environment terraform is owned by an infra team, so the confirm gate is not paranoia
about a local plan; it is about what a merged `.tf` change does.
Output: `.pi/extensions/safety/infra.ts` and `tests/unit/infra-policy.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local CLI → live AWS account | The machine holds live AWS SSO credentials for an account where `main` auto-deploys; a mutating `aws` call has no undo |
| local CLI → live Kubernetes cluster / terraform state | `kubectl delete` and `terraform destroy` are irreversible; `terraform state rm` silently orphans real resources |
| secret-returning API responses → model context | `get-secret-value` / `get-parameter` put plaintext credentials into the conversation permanently |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-31 | Tampering | mutating `aws` / `kubectl delete` / `terraform apply\|destroy\|import` | mitigate | Three-valued classification routing to the approval protocol; unknown verbs default to `confirm`, which is a terminal block headless |
| T-04-32 | Information Disclosure | `secretsmanager get-secret-value`, `ssm get-parameter`, `sts assume-role`, `configure get` | mitigate | `isSensitiveAwsRead` is evaluated BEFORE `isSafeAwsOperation`, so the `^get-` safe prefix cannot rescue a credential-returning operation; ordering pinned by a fixture and recorded as a falsification |
| T-04-33 | Denial of Service | approval fatigue | mitigate | `aws sts get-caller-identity` and `aws s3 ls` are NAMED allow rows with a `why` citing Pitfall 4 — gating the orientation calls trains reflexive approval, which is worse than no gate |
| T-04-34 | Elevation of Privilege | global-flag confusion (`aws --profile prod s3 rm`) | mitigate | Value-taking global flags tabulated and skipped before service/operation extraction; pinned by a fixture |
| T-04-35 | Elevation of Privilege | `kubectl exec` running arbitrary commands inside a workload | mitigate | Classified `confirm` — the bash AST guard cannot see into a remote shell, so the gate is the only control at that boundary |
| T-04-36 | Elevation of Privilege | alternate infra clients (`az`, `gcloud`, terraform via a wrapper script, `npm run deploy`) | accept | Out of scope for this phase's verb list; recorded as out-of-scope corpus rows in Plan 11 and published in `docs/SAFETY.md` |

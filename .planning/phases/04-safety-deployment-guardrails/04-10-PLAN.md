<objective>
Close the requirement that Pitfall 15 exists to force: prove the guard is present and
enforcing inside a spawned headless child process, using the child's own audit log as the
evidence — and prove the audit stream survives several processes writing it at once.

Purpose: the failure signature this guards against is the nastiest in the phase. A guard that
fires in the main session and never appears in the subagent audit log reads as "the subagent
did nothing dangerous" rather than "the guard was absent". Only an ALLOW row from inside the
child distinguishes those two, which is precisely why SAFE-14 requires allows and not just
blocks.
Output: `tests/integration/subagent-block.test.ts` and `tests/integration/audit-concurrency.test.ts`.
</objective>

Assertions:

2. `readTornSafe` reports zero torn lines. Use the TOLERANT reader here for the same reason
   Phase 2 does: a torn record is a measurement, not an exception, and throwing would turn a
   quantitative result into a stack trace.
3. Both `verdict === "allow"` and `verdict === "block"` rows appear across the four children,
   and every row parses as a complete object with the full `AuditRow` field set. This is the
   new assertion relative to the diagnostics analog: the concurrency proof and the
   allow-and-block proof are the same file here.
4. Every row carries a `pid`, and the set of distinct `pid` values has size four. Without
   this, one child writing all the rows would satisfy assertions 1-3.
5. Rotation under concurrency: drive one child past a small `rotateBytes` cap and assert no
   record was lost across the rename, mirroring the diagnostics rotation proof.

Use `withTempLogCwd` so nothing is written inside this repository.

Create `tests/integration/headless-deny.test.ts`. This must be a REAL spawned process, not a
faux session: `hasUI()` is an object-identity check against the `noOpUIContext` singleton, so
only an actual `--mode json` run proves the branch. Use `requirePiOnPath()` and `runPi()`.

Composition, which has not been done in this repo before and is the expensive part:
- a throwaway `PI_CODING_AGENT_DIR` (mkdtempSync) holding the safety extension at user scope
  via `writeUserScopeShim`;
- a throwaway cwd (mkdtempSync, outside this repository — the faux-session lesson about this
  repo's 49 KB CLAUDE.md being pulled into every request applies to a spawned `pi` too);
- `withLoopbackCompletions` scripting a canned assistant turn that emits a `bash` tool call
  for a blocked command, using its `respond` override;
- a temp `models.json` on disk pointing at the loopback `baseUrl` (a spawned process reads a
  file; it cannot see an in-process registry — state explicitly in a comment which helper is
  and is not applicable, since `withModelsConfig` builds an in-process `ModelRuntime`);
- `runPi(["--mode", "json", ...])` parsing the JSONL output lines.

Four cases:
1. DENY — the tool execution result for the blocked command is an error carrying the guard's
   reason. Assert on the parsed `tool_execution_end` (or equivalent) JSONL line, not on raw
   stdout text.
2. NO UI — assert that no interactive prompt was emitted and the process exited without
   hanging. The absence of a hang IS part of the requirement: an inline `confirm()` under
   `--mode json` returns `false` immediately, but an inline `select()` returns `undefined`,
   and a guard that treated `undefined` as "not refused" is the fail-open shape.
3. POSITIVE CONTROL — the SAME harness, same loopback script, same throwaway dirs, but
   emitting a benign command, executes successfully. Without this, case 1 is consistent with
   "the spawned process cannot execute anything at all", which is the most likely way this
   test lies.
4. AUDIT — `.pi/logs/audit-*.jsonl` under the spawned process's cwd contains a block row for
   case 1 and an allow row for case 3. This is the row that later proves the guard was
   loaded rather than that nothing happened.

Never `it.skip`. If `pi` is not on PATH, `requirePiOnPath()` throws with the remedy.

**Fallback, per RESEARCH Open Question 2**: if the loopback-driven tool call proves too
fragile to script reliably, fall back to invoking the blocked command through `pi --mode json`
by whatever route reliably reaches the wrapped tool, and record precisely what the fallback
does and does not prove in the SUMMARY. Do not silently downgrade to a faux-session test —
that would assert the wrong mechanism entirely.

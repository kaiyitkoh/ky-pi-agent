<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| corpus data → guard verdict | The corpus is the only place the phase's coverage claim is expressible; a mis-tagged row is a silent coverage hole |
| published doc → user's mental model | An overclaiming limits table is worse than none: it makes the user trust the guard in exactly the cases where it does not hold |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-54 | Repudiation | corpus bucket tuning | mitigate | A row may not be moved to OUT-OF-SCOPE to make a test pass; every bucket change during authoring must be recorded in the SUMMARY as either a code fix or a published limit. The doc cross-check makes reclassification visible rather than silent |
| T-04-55 | Spoofing | doc/corpus drift | mitigate | The published table's expected contents are DERIVED from `EVASION_CORPUS`, with a converse assertion that the doc holds no row the corpus does not; a hand-typed count is explicitly forbidden, copying `truncationCauseCount()`'s discipline |
| T-04-19 | Elevation of Privilege | PATH shadowing, task-runner indirection, encoding | accept | Genuinely not catchable by a bash-AST guard. Published in `docs/SAFETY.md` with the compensating control (GitLab server-side branch protection, SAFE-01) named in the same row |
| T-04-41 | Elevation of Privilege | extension-registered tools that shell out internally | accept | Out of scope for a guard that wraps four named built-in tools. Published, not silently claimed as covered |

| T-04-57 | Denial of Service | over-blocking benign commands | mitigate | Assumption A3's false-positive-risk case is in the corpus with the guard's actual behaviour recorded and a `why` stating whether the over-block is acceptable |

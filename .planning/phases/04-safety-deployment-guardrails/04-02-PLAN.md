Extract the Phase 2 JSONL machinery into a neutral shared module so the safety audit log
(SAFE-14) reuses a writer that already survived rotation races, path-confinement
falsification and a four-concurrent-process append proof — without `safety/` importing
anything from `diagnostics/`.

exactly Pitfall 15's failure signature. Allows must be recorded too, and the writer that
records them must be the hardened one, not a second one written under time pressure.
Output: `.pi/lib/jsonl.ts`, `.pi/extensions/safety/{schema,audit}.ts`, `diagnostics/jsonl.ts`
reduced to a thin binding, and the append-only gate re-pointed in the same commit.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| guard decision → `.pi/logs/audit-*.jsonl` | The only durable record of what the guard did; multiple OS processes (main session + subagents) append to one file |
| `base` string → filesystem path | An attacker-influenced or buggy base could place a write outside the log directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Repudiation | audit log | mitigate | Append-only `appendFileSync` writer (no stream, no held fd), open-write-close per record, rename-based rotation — reused from Phase 2 rather than reimplemented; ALLOW rows recorded alongside BLOCK rows so an absent guard is distinguishable from an uneventful session |
| T-04-10 | Information Disclosure | audit row contents | mitigate | Row shape is fixed to `{ts, event, tool, command, cwd, verdict, reason, pid}` in `safety/schema.ts`; tool OUTPUT and file CONTENTS are never written, so DIAG-07's credential-logging concern is not recreated in a second stream (RESEARCH Pitfall 6) |
| T-04-13 | Tampering | shared writer extraction | mitigate | `BASE_RE` character allowlist AND `assertInsideLogDir` resolved-path containment both move unchanged — Phase 2 falsification proved each catches inputs the other does not, so weakening either during the move is the regression the re-pointed `jsonl-append-only.test.ts` gate exists to catch |
| T-04-14 | Denial of Service | log retention | mitigate | `pruneLogs` requires caller-supplied `ownedBases`; no shared hardcoded list, so neither binding can delete the other's logs on `session_start` |
| T-04-15 | Repudiation | failed audit write | accept | `writeAuditRow` swallows its own write failure rather than converting a BLOCK into an exception that could be caught upstream as an allow. Residual risk stated in the SUMMARY; compensating control is Plan 10's concurrency/liveness proof and SAFE-12's use of the log as evidence |
</threat_model>

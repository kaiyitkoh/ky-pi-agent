<objective>
Build the path layer: one canonicalisation function that survives every path form this
machine actually produces, and three policies over it — sensitive-read blocking (SAFE-06),
out-of-project write/delete blocking (SAFE-08), and deferred-detonation target blocking for
the non-bash `write`/`edit` surface (SAFE-13).

Purpose: SAFE-06 exists because `.tfstate` holds plaintext secrets that would enter the
model's context window; SAFE-13 exists because a `write` into `.git/hooks/pre-commit` is a
bypass that no bash matcher ever sees and that a later benign command detonates. Both reduce
to "compare a parsed argument against a path", and on Windows that comparison is where the
whole thing quietly fails.
Output: `.pi/extensions/safety/paths.ts` and `tests/unit/path-policy.test.ts`.
</objective>

Create `.pi/extensions/safety/paths.ts` as a PURE module — no `ctx`, no filesystem reads, no
default export. Home directory and cwd are CALLER-SUPPLIED parameters, never read from
`process.env` inside the module: that is what makes `tests/unit/path-policy.test.ts` a
millisecond fixture test rather than a test of this developer's machine, and it is why the
`~/.aws/credentials` rule can be proven on a machine where that file does not exist
(an SSO machine typically has no such file — the rule is still required).

Export `canonicalisePathArg(arg, { cwd, home })` where `arg` carries BOTH the raw source
slice (`text`) and the escape-resolved form (`value`) from unbash's `Word`. Normalise on
`text` after stripping surrounding quote characters, because the executed finding is that
unquoted backslashes are consumed as POSIX escapes and `value` never sees the intended
Windows path. Where the argument came from a tool parameter rather than a parsed word
(the `read`/`write`/`edit` surface), the caller passes the same string as both.

The normalisation pipeline, in order: strip matched surrounding quotes → expand a leading
`~` or `~/` and a leading `$HOME`/`${HOME}` against the supplied `home` → detect and rewrite
`/cygdrive/<x>/` and `/<x>/` single-letter MSYS drive prefixes to `<X>:/` → convert every
backslash to a forward slash EXCEPT in a leading UNC `\\` pair (mirror the drive-letter vs
UNC discrimination `bin/bootstrap.sh:63-83` already does for `PI_AGENT_DIR`, and cite it) →
resolve against `cwd` if still relative → collapse `.` and `..` segments → upper-case a
leading drive letter only.

Write `tests/unit/path-policy.test.ts` with the canonicalisation table first: every row in
`<behavior>` as `{ input, cwd, home, expected, why }`. The equivalence assertions matter more
than the individual values — assert that the unquoted, double-quoted, single-quoted, `/c/`,
`/cygdrive/c/` and `C:/` forms of one path all produce ONE canonical string, because the
warning sign Pitfall 3 names is a rule that fires for the quoted form and silently passes
the unquoted one.

|----------|-------------|
| parsed path argument → policy comparison | The comparison is where a Windows path form silently stops matching, turning a block into an allow with no error anywhere |
| `write`/`edit` tool params → filesystem | A non-bash surface that no bash matcher inspects; the payload detonates later under a benign command |
| blocked file contents → model context window | SAFE-06's actual concern: `.tfstate` holds plaintext secrets that become permanently part of the conversation |

<objective>
Build the git and glab decision layer: a two-step evaluation that asks "is HEAD currently
the protected branch?" separately from "is this subcommand a write to the checked-out
branch?", and denies only when both hold.

Purpose: `git worktree add -b feat main` is the single most useful escape hatch the user has
— it reads `main` to create an unrelated branch and never mutates it. A naive "block any git
command mentioning main" rule breaks it while trying to protect main, which is the failure
Pitfall 5 names. `glab mr merge` is separate and unconditional: in the user's work repo the
MR merge is what deploys to AWS.
Output: `.pi/extensions/safety/git.ts`, `tests/unit/git-policy.test.ts`,
`tests/integration/git-head-main.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local checkout state → policy decision | `HEAD` is read from a repository the command chose (`-C`), not the one the harness assumed |
| local git/glab command → GitLab server | `glab mr merge` crosses into an environment where the merge immediately deploys to AWS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-25 | Tampering | write to `main` while checked out | mitigate | Two-step evaluation: `git symbolic-ref --short HEAD` in the invocation's resolved cwd, then a per-subcommand write/read classification. Deny only when both hold |
| T-04-26 | Elevation of Privilege | deploy trigger | mitigate | `glab mr merge` blocked unconditionally on every branch, with `mr list`/`mr view`/`ci status` allowed so the harness stays usable (decision 13) |
| T-04-18 | Elevation of Privilege | `git -C /other/repo push` | mitigate | `cwdOverride` from `shell.ts` selects the repository the HEAD oracle interrogates; proven by a two-repository integration case |
| T-04-27 | Denial of Service | over-broad `main` matching | mitigate | `git worktree add -b feat main`, `fetch`, `diff`, `log`, `rebase <other>` are NAMED allow rows and the worktree case is EXECUTED for real, closing Pitfall 5 |
| T-04-28 | Elevation of Privilege | unknown git/glab subcommand | mitigate | Defaults to block when HEAD is protected; the documented remedy is to add a read-table entry with a fixture, never to widen the default |
| T-04-29 | Spoofing | detached HEAD | mitigate | Reported as a distinct named value and asserted as such, so a caller cannot accidentally read `undefined` as "not main" |
| T-04-30 | Tampering | alternate git clients (`hub`, raw `curl` to the GitLab API with `$GITLAB_TOKEN`) | accept | Not enumerable by a verb-list guard. Recorded as an out-of-scope corpus row in Plan 11 and published in `docs/SAFETY.md`; the compensating control is SAFE-01 server-side branch protection |
</threat_model>

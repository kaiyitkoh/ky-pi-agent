<objective>
Give the harness a two-hop chain that survives a quota wall, a rate limit and an outage — and
that refuses to waste a second provider on a 400.

Purpose: the registry's completion entry point has **no** retry at all, and a nested call fires
no extension hooks, so the chain cannot live in a hook — it is a thin wrapper around the Phase 2
`callModel` chokepoint (RESEARCH §Q4.5). Not `pi.setModel()`, which is Phase 5's mode-switch and
would leave the session on the fallback model after a transient blip; not
`before_provider_request`, which can replace a payload but cannot change which provider is
dialled; not a third-party extension's `fallbackModels`, which is Phase 7.

The chain is **DeepSeek-direct → DashScope**. Qoder is not a provider and is not in v1. Routing
itself is Phase 5's job; this plan owns the chain for three named error classes only.

Output: `callWithFallback`, its taxonomy, and the per-provider attempt-count test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a failed request → a second provider | Advancing sends the user's prompt, system prompt and tool schemas to a different vendor than the one they selected |
| provider error text → the class decision | The classification is made from a string the provider controls |
| `providers/` → `diagnostics/` | The one sanctioned path to a model is the Phase 2 chokepoint; everything else is a build failure outside `diagnostics/` |

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |

Every hop is recorded by the Phase 2 turns row because the call goes through the chokepoint |
| T-03-10-02 | Information Disclosure | HIGH | a request advancing to DashScope after an **expired-credential** failure, sending the payload somewhere on the strength of a local misclassification | mitigate | The six SSO strings classify as `fatal` (they match neither of Pi's retryable patterns), and plan 03-08's classifier only ever moves a message toward non-retryable; the fatal case asserts the second provider's attempt count is 0 |

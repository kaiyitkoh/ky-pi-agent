<objective>
Make PROV-02 a mechanical gate on both surfaces where the rule actually applies.

Purpose: the rule is not "which file" but "which call site". `!command` values are cached for
the process lifetime only where the auth store resolves `credential.key`
(`resolve-config-value.ts:139-146, :196-204`; `auth-storage.ts:442-448`). A `!command` in
`models.json`'s `apiKey`/`headers` — **or in a provider registration's `apiKey` string from an
extension** — goes through the uncached resolver and is re-executed on **every provider
request**, with no cache, no TTL, no stale reuse and no recovery. That is a subprocess spawn in
the hot path. Trap T13 is exactly the mistake of scanning only the template and declaring
PROV-02 satisfied.

Output: `tests/unit/command-interpolation.test.ts`.
</objective>

| Boundary | Description |
|----------|-------------|
| config value → subprocess execution | A leading `!` in a resolved config value causes Pi to execute a shell command |
| per-request resolution → the hot path | The uncached resolver runs inside every provider request, on a laptop where latency is already the complaint |
| test fixture → the scanned directories | A fixture carrying the forbidden shape, written where the scan looks, fails the gate it exists to prove |

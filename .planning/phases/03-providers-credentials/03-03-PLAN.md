  <action>
Create `tests/helpers/loopback.ts` exporting `withLoopbackCompletions(opts, fn)` and a named
refusal helper (`assertLoopbackUrl` or equivalent) that is exported so a test can prove it
fires.

Server: `node:http` only, `listen(0, "127.0.0.1")`, port read back from `server.address()`.
Expose `baseUrl` as `http://127.0.0.1:<port>/v1` on the handle. Accept any path under that
base; do not hard-code `/chat/completions`, because the adapter's exact path is Pi's business
and a mismatch should surface as a captured request with an unexpected `url`, not as a hang.

Capture: for every request, buffer the body to a string, record
`{ method, url, headers, rawBody, body }` where `body` is `JSON.parse(rawBody)` when it parses
and `undefined` otherwise (never throw inside the request handler — a parse failure must
arrive at the test as data). Push each record onto a `requests` array on the handle, in order.

Response: by default reply `200` with `content-type: text/event-stream` and a minimal valid
OpenAI-completions SSE sequence — one chunk carrying a short assistant text delta, one final
chunk carrying a `finish_reason`, then `data: [DONE]` — so the adapter call resolves cleanly
instead of hanging or producing an unhandled rejection. Allow `opts.respond` to override the
whole response for a test that needs an error shape. The assertion the caller cares about has
already been captured before the response is written, so a test may also assert and let the
default reply run.

Refusal (Trap T11, a **helper-level** obligation, not a test-level one): export a function
that takes a resolved base URL and throws a loud `TypeError` unless its hostname is exactly
`127.0.0.1`, with the remedy and the reason in the message — a copy-paste that reintroduces a
real host must fail rather than silently egress from CI. Call it from inside
`withLoopbackCompletions` on the URL it is about to hand out, so the guard cannot be forgotten
by a caller.

Teardown: close the server in the `finally` and **await** the close, so the port is released
before the next test binds; destroy any lingering sockets so a keep-alive connection cannot
hold the process open. Follow "throw, never skip": if the server fails to bind, throw with the
remedy — there is deliberately no skip escape hatch anywhere under `tests/helpers/`.

Open with the house module docstring: what it is, why it exists, the `detectCompat`
byte-identity argument with its `[VERIFIED:]` citation, the explicit statement that this
proves what Pi **emits** and says nothing about what DashScope **accepts** (RB-03-01,
RB-03-02), and PROV-03 / PROV-10 named as the requirements served.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process → the network | A test that issues a real provider request from a machine with no credentials is at best noise and at worst egress from CI |
| captured request body → test output and CI logs | Whatever the adapter sends is now sitting in memory and may be printed by a failing assertion |
| bound port → the rest of the suite | A leaked listener holds a port and a handle for the remainder of the run |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Information Disclosure | a copy-paste pointing the capture at a real provider host, issuing a live request from CI | mitigate | The refusal is enforced inside the helper, not left to the test, and throws before the URL is handed out; Task 2 asserts it fires and asserts its paired positive (Trap T11) |
| T-03-03-02 | Information Disclosure | a captured `authorization` header printed verbatim by a failing assertion | accept | No credential exists on this machine and the loopback provider's key is a fixture; the wire redactor already covers the instrumented path. Revisit only if a live key is ever used against a loopback server, which nothing in this phase does |
| T-03-03-03 | Denial of Service | a leaked listener or keep-alive socket holding a port and stalling the suite | mitigate | The server is closed and awaited in the `finally`, lingering sockets are destroyed, and two cases assert the port is released — one after a clean return, one after a throw |
| T-03-03-04 | Denial of Service | the adapter hanging because the fake response is not a valid stream | mitigate | The default reply is a minimal valid SSE sequence terminating in `data: [DONE]`, asserted by case 2 |
| T-03-03-05 | Repudiation | a server that captured nothing, making every later assertion vacuously green | mitigate | `requests.length` is asserted non-empty before any content assertion, per the standing house rule |
| T-03-03-SC | Tampering | npm/pip/cargo installs | mitigate | `node:http` only. `tests/unit/pinning.test.ts` asserts `devDependencies` equals exactly the six audited pins and would go red on any test-server package |

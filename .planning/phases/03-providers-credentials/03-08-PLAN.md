<objective>
Turn a daily, silent, wall-clock-burning failure into one line that tells the user exactly what
to type.

Purpose: `formatBedrockError` maps exactly five exception names, none of them credential expiry
(`bedrock-converse-stream.ts:335-341, :357-374`), so an SSO expiry arrives as a raw SDK string
with no reauth instruction — and SSO sessions are 8-12 hours, so this fires roughly daily on a
working day. The mechanism is `message_end`, **not** `after_provider_response`: that hook never
fires on a provider error, twice over (Trap T2, RESEARCH §Q4.1). A `message_end` handler that
rewrites `errorMessage` controls Pi's retry decision, because the retry gate reads the message
**after** handlers have mutated it in place (RESEARCH §Q4.4).

One honest correction to carry into the code comments: all six named credential strings are
**already** non-retryable under Pi 0.84.1 — RESEARCH executed the regexes. The verified gap is
the **message**. The residual retry risk is narrow but real: a credential failure whose text
happens to contain `timeout`, `fetch failed`, `socket hang up`, `getaddrinfo` or a 5xx status
would be retried 3× at 2s/4s/8s against a credential that cannot become valid.

Output: `.pi/extensions/providers/`, and the integration test that proves both halves.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider error text → the classifier's regexes | Untrusted, unbounded text from an external service is matched by patterns running inside the agent loop |
| a rewritten message → Pi's retry gate | Rewriting `errorMessage` changes whether Pi burns wall-clock against a credential that cannot become valid |
| a surfaced error → the user's terminal | Whatever this handler writes is what the user believes happened |
| `providers/` → `diagnostics/` | Phase 2's instrument is asserted by hook count and command count and must stay sealed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-03-08-02 | Denial of Service | the rewrite re-admitting retryable text and burning 3 retries at 2s/4s/8s against a dead credential | mitigate | The original SDK text is kept out of `errorMessage` (Trap T4), and every fixture is asserted non-retryable after the rewrite |

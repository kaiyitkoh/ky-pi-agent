Pre-registering the rule in code before any data exists is what makes the eventual answer trustworthy.

## Protocol (pre-registered; source 10-RESEARCH "CTX-05 design", choices recorded here)

- Corpus: the six Phase 8 seeded defects (`SEEDED_DEFECTS`, tests/fixtures/seeded-defects/index.ts:316), each built into a disposable temp repo by `build(repo)`; grader `scoreCalibration` (quality/calibration.ts:93). Task prompt: `REVIEWER_SYSTEM_PROMPT` + `buildReviewerContext(...)` delivered as the USER message in every arm, plus one fixed output instruction: do not call a tool; output the review as one JSON object matching the submit_review arguments in a ```json block (so no arm can win by having a tool the other lacks, and the reviewer contract is the same in all arms).
- Arms (same model, route, thinking level; temperature untouched):
  - A minimal: bare Pi, no extensions/skills/context files/prompt templates, built-in tools read, bash, edit, write.
  - B harness-implement: the harness as installed, `--ky-profile implement` (the default).
  - F harness-full: the harness, `--ky-profile full`.
  - C padded-minimal: A plus `--append-system-prompt <file>` whose content is inert real harness prose sized to PAD_TOKENS = (measured F floor - measured A floor), separating token mass from harness behaviour.
  Exact flag spellings verified in node_modules/@earendil-works/pi-coding-agent/docs/cli.md before coding (RESEARCH cites `-ne -ns -nc -np --tools ... --mode json -p`).
  An optional strong-model ceiling arm and a custom-prompt arm are NOT part of this pre-registered protocol (recorded so their absence is a decision, not an omission).
- Design: paired by (defect, repeat); repeats R=10 first stage (60 trials per arm, 240 total), R=20 only if INCONCLUSIVE, then stop. Seeded interleaved order cancels provider drift.
- Primary comparison: A vs F (minimal vs full harness). Secondary: A vs B, A vs C. Primary metric: per-trial binary catch from scoreCalibration. Secondary: unmatched findings (noise), prose-tool-call rate per assistant message via isProseToolCall, input tokens and cacheRead, stop reason, malformed-output rate.
- Interval: Newcombe hybrid score interval (method 10, Wilson-based) for the difference of two proportions at 90% two-sided (z = 1.6449). Chosen over an "exact" interval because it is closed-form, needs no dependency, and has well-documented coverage; verified in tests against Newcombe (1998) worked example 56/70 vs 48/80 at 95%: 0.0524 to 0.3339.
- Decision rule, d = catch(F) - catch(A): DEGRADES if d <= -DEGRADE_POINTS (0.15) and the interval's upper bound < 0; NO_DETECTABLE_EFFECT if the interval's lower bound > -DEGRADE_POINTS; otherwise INCONCLUSIVE. The protocol states it can only detect large effects (about 23 points at 60/arm under an optimistic independence assumption); INCONCLUSIVE is a legitimate recorded answer.
- Discrimination (pure function over the summary; thresholds as constants): F<A and C≈A -> harness behaviour; F<A and C<A -> context pollution; no arm differs and catch rate low -> neither, check prose and provider; prose-tool-call rate >= PROSE_RATE_THRESHOLD (0.10) in any arm with low-catch trials concentrated in prose trials -> prose tool calls; "≈" means the C vs A interval's lower bound > -DEGRADE_POINTS. Provider misconfiguration is discriminated by the runbook step that runs arm A on two routes; the function accepts an optional second-route summary.

Output: one pure module in diagnostics/ (named exports only, no model call, no default export) and its test file.

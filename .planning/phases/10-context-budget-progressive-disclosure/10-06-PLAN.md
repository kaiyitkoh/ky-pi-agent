<objective>
Make the experiment runnable by one command on the work laptop, prove the loop offline against a fake `pi`, and document the protocol.

Purpose: CTX-05 must be built and verified offline with the live run deferred to RB-10-01 (10-CONTEXT fact 6). The minimal arm has no safety layer and gets bash on a laptop holding live AWS SSO credentials, so the environment scrub is a load-bearing control and is tested, not just written.

Design (recorded):
- Repo convention is POSIX sh for scripts (AGENTS.md); the sh launcher owns the loop and the env scrub (auditable in one screen). Argument construction, corpus building and statistics stay in typed code: `scripts/ctx-experiment.mjs` imports `.pi/extensions/diagnostics/ctx-experiment.ts` (and the seeded-defect fixtures) and relies on Node's built-in type stripping (Node >= 22.19 per engines; verified on 24.16 by research, A5 — the runbook entry tells the operator to check `node --version` and fall back to `--experimental-strip-types` if a 22.x build rejects the import).
- Inputs by env var, all validated by the launcher before any trial: `KY_EXP_MODEL` (provider/model id, same for every arm), `KY_EXP_KEY_VAR` (NAME of the env var holding the provider key; its value is passed through, nothing else), optional `KY_EXP_SEED` (default 20261013), `KY_EXP_REPEATS` (default FIRST_STAGE_REPEATS), `KY_EXP_DEFECTS` (comma list filter, default all six), `KY_EXP_PI` (pi binary, default `pi`), `KY_EXP_OUT` (default `logs/ctx-experiment/<UTC timestamp>`).
- Per trial: a fresh temp dir holding the built defect repo, a temp HOME, and a temp agent dir. Arms B and F get `settings.json` in that agent dir whose `packages` lists this repo's absolute path (a local Pi package source, docs/settings.md:151 and docs/packages.md; verify the local-path form at source before coding); arms A and C get an agent dir with no packages. Output: `<out>/trials.tsv`, `<out>/<trialId>.jsonl`, `<out>/summary.json`, and the human summary on stdout.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| launcher -> pi (minimal arm) | A model with bash and no safety layer runs on a laptop holding AWS SSO credentials |
| operator env -> trial env | Provider key crosses; nothing else may |
| trial output -> disk | Model output written under logs/ |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-21 | Elevation of privilege | minimal arm bash on live laptop | mitigate | `env -i` scrub with explicit allowlist; HOME/USERPROFILE/PI_CODING_AGENT_DIR/TMP point at a per-trial temp root; cwd is a disposable temp repo; prompt is review-only; tested with polluted AWS_* vars that must not appear |
| T-10-22 | Information disclosure | provider key | mitigate | Passed only as the named variable; launcher never prints its value; results never contain it (pi stream carries no key) |
| T-10-23 | Information disclosure | results committed by accident | mitigate | Output under `logs/` which is gitignored, as is `*.jsonl` |
| T-10-24 | Tampering | shell argument injection | mitigate | No eval; args read line-wise with `set -f`; prompt passed as one quoted argument |
| T-10-25 | Tampering | arm B/F package source | mitigate | Local package path is this repo's own checkout; no registry fetch during trials |
</threat_model>
